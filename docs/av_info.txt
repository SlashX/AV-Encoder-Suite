1. STRUCTURA PROIECTULUI
═══════════════════════════════════════════════════════════════

  233 fisiere totale (22 src + 1 UI web + 18 tools + 6 profile +
  3 burnin presets + 6 Python engines + 170 test_* scripts + 7 infra).

  Pentru structura completa a folderelor si lista de fisiere
  vezi README.md (Project Structure tree).

  ROL PE PLATFORMA:
    Termux / Linux / macOS  →  bash (av_launcher.sh deschide encoderele
                                separate prin av_common.sh)
    Windows                 →  PowerShell (av_encode.ps1 all-in-one,
                                independent de scripturile bash)

  PRINCIPIU CHEIE:
    Orice feature din bash este oglindit in PS1 — atat la nivel de
    functionalitate, cat si la nivel de structura fisiere (telemetrie
    si GPS extern au mirror-uri PS1 standalone).

  TOOLS (src/tools/):
    Scripturile din tools/ sunt STANDALONE — se ruleaza manual cand
    vrei sa instalezi/actualizezi dependinte externe (hdr10plus_tool,
    dovi_tool, ExifTool). NU sunt apelate automat din encodere.

  PASUL 2 — Update + dependinte:
            pkg update && pkg upgrade -y
            pkg install ffmpeg termux-api -y

  PASUL 3 — Acces la stocare:
            termux-setup-storage     # accepta permisiunea

            Dupa aceea poti folosi /storage/emulated/0/ (memoria interna).

  PASUL 4 — Dependinte optionale:
            pkg install exiftool python -y     # telemetrie + GPS
            ./tools/exiftool_update.sh         # smart updater (cu fallback build manual)
            ./tools/hdr10plus_parser.sh        # HDR10+ (HEVC) — compileaza din sursa
            ./tools/dovi_parser.sh             # Dolby Vision (HEVC)
            ./tools/av1hdr10plus_parser.sh     # HDR10+ AV1 (sven-pke fork)
            ./tools/av1dovi_parser.sh          # Dolby Vision AV1 (sven-pke fork)
            ./tools/openapv_validator.sh       # decodor referinta OpenAPV (v69,
                                               #   optional — decode-check APV)

                                               #   dvcC Dolby Vision pe MKV

                                               #   dvcC Dolby Vision pe MP4/MOV
                                               #   [HEVC v71 + AV1 v72])

  PASUL 5 — Permisiuni:
            chmod +x src/*.sh src/tools/*.sh

  PASUL 6 — Lanseaza:
            cd src && ./av_launcher.sh

  ─── 3.4. Windows ───

    1. Descarca FFmpeg full build de la: https://www.gyan.dev/ffmpeg/builds/

      portabil MKVToolNix — activeaza semnalizarea Dolby Vision de container
      (dvcC) pe hibridele HEVC salvate in MKV (DV redat si pe televizoare).

  PASUL 4 — Lansare:
    cd src
    .\av_encode.ps1

6. FLUX ENCODARE — CUM FUNCTIONEAZA
═══════════════════════════════════════════════════════════════

  Fluxul este identic pe toate platformele. Diferenta: pe Termux/Linux/macOS
  av_launcher.sh deschide scriptul separat per encoder; pe Windows totul e
  intr-un singur fisier (av_encode.ps1).

  PASII LOGICI (per fisier video, simplificat):
    1. Verifica daca output-ul exista deja (skip / re-do)
    2. Detecteaza track-uri DJI (djmd/dbgi/tmcd/cover) → se elimina la
       encode, GPS-ul nativ se re-adauga dupa (MP4/MOV, v78 — vezi 8.6)
    3. Detecteaza HDR (color_transfer + side_data + codec_tag)
    4. Detecteaza Dolby Vision / HDR10+ / LOG / HLG → dialog dedicat
    5. Smart stream copy detection (v38): daca codec source == target si
       nu sunt transformari planificate → prompt opt-in skip re-encode
    6. Seteaza CRF auto (per rezolutie) sau foloseste CRF/VBR custom
    7. Aplica resize / FPS / filtre daca selectate
    8. Construieste parametri encoder
    9. Lanseaza ffmpeg cu progress file
   10. Afiseaza progress bar real (label dinamic, FPS, ETA, %)
   11. Stderr capturat in fisier temporar — pe error tail -10 inline
   12. La finalizare: logheaza dimensiuni, timp, spatiu salvat

  DRY-RUN (v23.1):
    Optiune in meniul de lansare. Parcurge tot batch-ul si afiseaza per
    fisier ce ar face (encoder, sursa, HDR, resize, FPS, filtre, audio,
    estimare dimensiune) — fara sa ruleze ffmpeg. Util pentru verificare
    inainte de batch lung.

  RESUME (v23.1):
    Fisierele encodate cu succes sunt marcate in batch_progress.log.
    La reluare, fisierele deja procesate sarite automat. La finalizare
    cu succes, batch_progress.log se sterge automat. Daca batch-ul e
    intrerupt (Ctrl+C, crash), .log ramane si pickup-ul e automat.

  PRESERVE FOLDER STRUCTURE (v33.3):
    Optiune la inceput batch: "Pastrezi structura de foldere?" (d/n).
    Daca d → scanare recursiva subfoldere + recreare in Output.
    Exemplu: Input/Airsoft/clip1.mp4 → Output/Airsoft/clip1_x265.mp4

  BATCH QUEUE (v33):
    Inainte de lansare, optiune optional "Editezi batch queue?".
    Comenzi interactive: X toggle, F muta pe prima, M muta de la→la,
    D doar acest fisier, Enter lanseaza.

  INTERACTIVE MODE (v30):
    Optiune in meniul lansare ("Normal / Dry-run / Interactiv").
    Dupa fiecare fisier: dialog Pastreaza setari / Modifica audio-CRF-
    normalize-filtru / Opreste batch. Util pentru batch-uri mixte.

  PROGRESS BAR REAL (v37/v38):
    "<LABEL>: NN% | FPS: X.X | ETA: HH:MM:SS"
    Label dinamic per encoder (LIBX265 / LIBX264 / AV1-SVT / AV1-AOM /
    DNXHR / ProRes / APV / *-NVENC / *-QSV / *-AMF / MediaCodec).
    Aplicat si pe stream copy, DV copy, HDR10+ copy, Trim/Concat re-encode.

7. OPTIUNI DETALIATE
═══════════════════════════════════════════════════════════════

  ─── 7.1. Encodere video ───

  libx265    — H.265/HEVC. Compresie ~40% mai buna decat H.264.
               Suporta HDR10, HDR10+, Dolby Vision, HLG. Recomandat general.
  libx264    — H.264/AVC. Compatibilitate maxima (orice dispozitiv).
               NU suporta HDR nativ (fara MaxCLL/MaxFALL/mastering).
               Profil selectabil: high (8bit), high10 (10bit), high422.
  libsvtav1  — AV1 via SVT. Rapid, recomandat pe telefon.
               Compresie ~20-30% mai buna decat HEVC. Suporta film-grain.
               HDR10+ inline (v1.5+), DV Profile 10 via post-encode inject.
  libaom-av1 — AV1 via libaom. Calitate maxima, foarte lent.
               Film-grain via denoise-noise-level. NU suporta HDR10+ inline.
  dnxhd      — DNxHR (Avid mezzanine, codec lossless optic — vezi 7.3).
  prores_ks  — Apple ProRes (codec lossless optic Apple — vezi 7.4).
  liboapv    — Samsung APV (codec profesional intra-frame, 10/12-bit —
               vezi 7.4.1). Numele encoderului difera intre build-uri
               (liboapv sau libopenapv) — suita il detecteaza automat.
               Necesita ffmpeg 8.1+ cu OpenAPV (nu in build-ul Termux
               standard). Decodarea APV e inclusa in ffmpeg 8.1 standard.


  ─── 7.2. Container ───

  mkv   — Flexibil, suporta orice codec / subtitlu / DV. Recomandat default.
          (Track-urile de date DJI au codec "none" → nu intra in niciun
          container; GPS-ul nativ se pastreaza altfel — vezi 8.6.)
  mp4   — Compatibil maxim (web, Smart TV, telefoane). +faststart.
          Incompatibil cu PGS/DVDSUB. GPS-ul nativ DJI se re-adauga
          automat dupa encodare (v78, vezi 8.6).
  mov   — Apple / Final Cut Pro. Aceleasi limitari ca mp4. + E-AC3 / AC3
          incompat.
  mxf   — Avid native. Folosit exclusiv cu DNxHR.
  webm  — Doar VP8/VP9/AV1 + Opus (vezi 7.10). Disponibil acum si in
          audio-only encoder (v53) — util cand sursa e deja WebM/VP9/AV1
          si vrei doar re-encode audio (Opus) fara sa schimbi containerul.
          Constrangeri verificate per-fisier: video sursa trebuie sa fie
          vp8/vp9/av1; subtitrarile/attachment-urile sunt strip (WebM
          accepta doar WebVTT).


  ─── 7.3. DNxHR — codec mezzanine profesional ───

  DNxHR este un codec video profesional dezvoltat de Avid, standard in
  post-productie broadcast si film. Spre deosebire de x265/x264/AV1
  (lossy, pentru distributie), DNxHR e un codec mezzanine — lossless
  optic, dimensiune predictibila, decodare rapida, perfect pentru
  timeline editing.

  CAND SE FOLOSESTE:
    - Trimiti material unui editor in Premiere/Resolve/Avid
    - Master intermediar fara degradare pentru editare/color grading
    - Sursa DVD/Blu-ray si vrei fisier editabil direct
    - Decodare rapida pe timeline (nu CPU-intensive ca x265)

  CAND NU SE FOLOSESTE:
    - Distributie finala (fisiere de zeci de GB pentru film intreg)
    - Stocare termen lung (foloseste x265 CRF 18-22 pentru arhivare)
    - Streaming sau upload (x265 / x264 / AV1)

  PROFILURI (toate 5):
    LB  ~45 Mbps  yuv422p (8-bit)   offline edit, spatiu limitat
    SQ  ~145 Mbps yuv422p (8-bit)   standard interchange [implicit recomandat]
    HQ  ~220 Mbps yuv422p (8-bit)   color grading intensiv / broadcast
    HQX ~220 Mbps yuv422p10le       10-bit HDR workflow (singur recomandat pt HDR)
    444 ~440 Mbps yuv444p10le       4:4:4 10-bit — VFX, compositing, keying

  DIMENSIUNI ESTIMATE (1080p/25fps, 1 ora material):
    LB ~20 GB / SQ ~65 GB / HQ-HQX ~99 GB / 444 ~198 GB.

  CONTAINERE: .mov (QuickTime — FCP/Premiere/Resolve) sau .mxf (Avid native).
  LIMITARI: track-uri DJI omise automat; PGS/DVDSUB incompatibile cu .mov;
            fara CRF / preset / tune / VBR — bitrate fix per profil.
  ANALIZA (v74): "Verifica fisiere media" afiseaza profilul DNxHR exact
            (Avid DNxHR LB / SQ / HQ / HQX / 444), citit din campul `profile`.
  HDR / Dolby Vision: profilurile HQX si 444 (10-bit) pastreaza imaginea si
            semnalizarea HDR10 / HLG. Pe surse HDR (PQ/HLG) DNxHR pastreaza
            tag-urile de culoare pe ambele containere. Pe surse LOG (transfer
            necunoscut) tag-ul de gamut bt2020 e container-driven: pastrat pe
            MXF (orice profil), pe MOV devine unknown (orice profil) — cosmetic,
            pixelii Log raman intacti. LB/SQ/HQ (8-bit) scad precizia 10->8 bit
            (recomandat HQX/444 pt 10-bit). Master-display se pastreaza pe ambele
            containere; MaxCLL doar pe MOV (muxer-ul MXF nu il scrie).
            Ca orice codec mezzanine, DNxHR NU poate purta metadata dinamica
            Dolby Vision (RPU) sau HDR10+ — sursele DV / HDR10+ ies ca HDR10
            standard (suita te anunta clar).
  MXF + audio: containerul .mxf accepta DOAR audio PCM (necomprimat). Daca alegi
            audio comprimat (ex. AAC) + .mxf, suita iti ofera audio PCM sau
            schimbarea containerului in .mov.


  ─── 7.4. ProRes — codec profesional Apple ───

  Encoder Apple intra-frame (prores_ks) — software, ruleaza pe TOATE platformele
  (Windows / Linux / Termux / macOS); varianta hardware VideoToolbox e doar pe macOS.
  Container .mov [implicit] sau .mxf (broadcast / Avid — v74; audio devine PCM).
  LOG format: pastrare automata (fara dialog, mesaj informativ).

  PROFILE:
    Proxy    ~45 Mbps   offline editing spatiu limitat
    LT       ~100 Mbps  light workflow
    Standard ~145 Mbps  interchange
    HQ       ~220 Mbps  [implicit recomandat] high quality broadcast
    4444     ~330 Mbps  4:4:4 (+ alpha doar daca sursa il are — v74)
    4444 XQ  ~500 Mbps  calitate maxima VFX / compositing (profil nativ XQ)

  v74: 4444 / 4444 XQ pastreaza canalul alpha DOAR daca sursa il are (altfel,
       fara plan alpha "gol" inutil); aceste doua profile ies pe 12-bit nativ
       (422 = 10-bit). "Verifica fisiere media" afiseaza profilul exact
       (Apple ProRes Proxy / LT / Standard / HQ / 4444 / 4444 XQ).

  HDR / Dolby Vision: ProRes pastreaza imaginea si culoarea HDR10 / HLG / Log
            intacte (422 = 10-bit, 4444/XQ = 12-bit). Ca orice codec mezzanine,
            NU poate purta Dolby Vision (RPU) sau HDR10+ dinamic — sursele DV /
            HDR10+ ies ca HDR10 standard (suita te anunta clar).


  ─── 7.4.1. APV — codec profesional Samsung ───

  Encoder Samsung intra-frame (OpenAPV), profesional, 10/12-bit. Necesita
  ffmpeg 8.1+ cu OpenAPV (encoderul `liboapv` sau `libopenapv`, detectat
  automat). Decodarea e inclusa in ffmpeg 8.1 standard.

  Spre deosebire de DNxHR / ProRes (bitrate fix per profil), APV are reglaje
  INDEPENDENTE (ca x265): alegi separat profilul, viteza si calitatea.

  PROFIL / PIXEL FORMAT (profil intern auto din pixfmt):
    4:2:2 10-bit  (422-10) [implicit]   interchange standard
    4:2:2 12-bit  (422-12)              precizie mai mare
    4:4:4 10-bit  (444-10)              grading / VFX
    4:4:4 12-bit  (444-12)              grading maxim
    4:4:4 + alpha 10-bit (4444-10)      compositing cu transparenta
    4:4:4 + alpha 12-bit (4444-12)      compositing maxim, alpha 12-bit (v74)

  PRESET VITEZA: fastest / fast / medium [implicit] / slow / placebo.
  QP (CALITATE): 0-63, mai mic = mai bun, implicit 32 (ca un CRF).
  EXTRA: parametri avansati optionali (-oapv-params key=value:key=value).

  CONTAINERE: mp4 / mov / mkv (NU mxf — ffmpeg nu poate pune APV in MXF).
  ANALIZA (v74): "Verifica fisiere media" afiseaza profilul APV exact (Samsung
            APV 4:2:2 / 4:4:4 / 4:4:4:4 + 10/12-bit), citit din campul `profile`.
  HDR / Dolby Vision: APV (10/12-bit) pastreaza imaginea + culoarea HDR10 /
            HLG / Log. Dolby Vision (RPU) NU poate fi purtat — sursele DV
            ies ca HDR10 standard (esti anuntat).

  HDR10+ PE APV (v69): metadata dinamica HDR10+ se PASTREAZA la encodarea
  APV — premiera (ffmpeg singur o pierde; suita o scrie per-cadru direct
  in fluxul APV printr-un motor propriu, impreuna cu mastering display +
  MaxCLL statice). La encode, pe surse HDR10+ esti intrebat:
    1) Pastreaza HDR10+ [implicit]  — metadata dinamica intacta in APV
    2) Doar HDR10 static            — comportamentul vechi
    3) Sare fisierul
  Functioneaza din ORICE sursa HDR10+ (HEVC / AV1 / alt APV) si invers:
  un APV cu HDR10+ poate fi re-encodat in x265/AV1 cu metadata pastrata.
  "Verifica fisiere media" detecteaza HDR10+ pe APV. Bypass non-interactiv:
  APV_HDR10PLUS_POLICY=preserve|static|skip (variabila de mediu).
  Optional: installerul tools/openapv_validator instaleaza decodorul de
  REFERINTA OpenAPV — cand exista, verificarea post-encode ruleaza automat
  si un decode-check oficial; cand lipseste, pasul e sarit in tacere.


  ─── 7.5. Surse DVD si Blu-ray ───

  Suita proceseaza direct fisiere .vob (DVD) si .m2ts/.mts (Blu-ray)
  FARA tooluri externe, cu conditia ca discul sa NU fie protejat
  (CSS pe DVD, AACS/BD+ pe Blu-ray comercial).

  Discuri NEPROTEJATE (filmate personal, backup propriu):
    → Copiaza fisierele in InputVideos si encodeaza normal.

  Discuri PROTEJATE (comerciale):
    → Necesita MakeMKV pentru decriptare inainte. Dupa decriptare,
      .mkv rezultat se proceseaza normal.

  .VOB (DVD):
    Video: MPEG-2 (aproape mereu interlasat).
    Audio: AC3 / DTS (surround), PCM.
    Subtitrari: dvd_subtitle (bitmap) — incompatibile mp4/mov (omise -sn),
                pastrate doar in mkv.
    ATENTIE DEINTERLACE: surse DVD sunt aproape mereu interlasate.
    Activeaza filtrul Deinterlace (vezi 7.8) pentru rezultate corecte.

    Optiuni launcher cand exista .vob in InputVideos:
      1) Encodeaza fiecare .vob individual
      2) Import titlu DVD complet — specifica calea VIDEO_TS/, launcher
         concateneaza VTS_01_1..N.VOB intr-un singur fisier.
         ATENTIE: VIDEO_TS/ nu trebuie sa contina spatii — protocolul
         concat: al ffmpeg nu suporta spatii.

  .M2TS / .MTS (Blu-ray):
    Video: H.264 / H.265, progresiv (de obicei — fara deinterlace).
    Audio: DTS-HD, TrueHD, AC3, AAC.
    Subtitrari: PGS (bitmap) — incompatibile mp4/mov, pastrate doar in mkv.

    Fisierele .m2ts sunt unice per titlu (de obicei BDMV/STREAM/XXXXX.m2ts) —
    se pun direct in InputVideos.

    v91: transport stream-urile de disc (.m2ts/.mts) au o structura de
    program care face ffprobe sa listeze fiecare pista de doua ori. Suita
    deduplica acum numaratorile afectate (numarul de subtitrari in "Verifica
    fisiere media" + dialogul de selectie audio per-pista, care nu se mai
    declanseaza fals pe un .m2ts cu o singura pista audio). Encodarea nu era
    afectata (maparea foloseste indecsi relativi) — doar numaratorile.


  ─── 7.6. Rezolutie output ───

  1) Pastreaza originala [implicit]
  2) 3840 (4K UHD)
  3) 2560 (2K / 1440p)
  4) 1920 (Full HD 1080p)
  5) 1280 (HD 720p)
  6) Custom (minim 320, numar par — ajustare automata daca impar)

  Filtru folosit: scale=WIDTH:-2 (aspect ratio pastrat, height par).
  NU face upscale automat: daca sursa <= target, ramane neschimbata.
  Dolby Vision stream copy: resize NU se aplica.


  ─── 7.7. Frame rate (FPS) output ───

  1) Pastreaza original [implicit]
  2) 60 / 50 / 30 / 25 / 24 / 23.976
  3) Custom (29.97, 48, 120, etc.)

  Dupa FPS, alegi metoda:
  1) Drop/duplicate frames [implicit] — rapid (-r FPS).
  2) Motion interpolation — calitate mai buna, FOARTE lent (10-20x).
     Recomandat doar pe PC. Pe telefon poate dura ore.

  NU face FPS upscale (30→60 ramane 30). Audio se sincronizeaza automat.
  Dolby Vision stream copy: FPS NU se aplica.


  ─── 7.8. Filtre video (optional) ───

  Filtrele se aplica per-fisier, dupa scale si inainte de FPS, combinate
  intr-un singur -vf. Nu afecteaza audio.

  1) Fara filtre [implicit]

  2) Denoise light — nlmeans h=1.0:s=7:p=3:r=5
     Pastreaza detalii fine (texturi, fir de par, text).
     Potrivit pt: 4K modern cu zgomot usor ISO, drone footage in lumina buna,
     camere de actiune.
     Performanta: ridicat (nlmeans e lent).

  3) Denoise medium — hqdn3d luma_spatial=4:chroma_spatial=3
     Filtru clasic rapid, eficient, ambele axe spatiale + temporale.
     Potrivit pt: zgomot moderat, encode-uri lungi unde viteza conteaza,
     arhiva digitizata.
     Performanta: scazut (hqdn3d e rapid).

  4) Denoise strong — nlmeans h=3.0:s=7:p=5:r=9
     Agresiv, fereastra mare. Elimina zgomot ridicat dar inmoaie detalii.
     Potrivit pt: VHS digitizat, TV analogic, footage nocturn ISO foarte
     ridicat, material cu artefacte compresie.
     Performanta: foarte ridicat.

  5) Sharpen light — unsharp luma_amount=0.8
     Ascutire clasica naturala. Mareste contrast local fara halos.
     Potrivit pt: footage neclar din miscare, downscale, material vechi.
     Performanta: scazut.

  6) Sharpen medium — cas strength=0.6
     Contrast Adaptive Sharpening (AMD CAS). Adapteaza per-pixel.
     Evita supraascutire in zone deja clare.
     Potrivit pt: footage modern, gaming capture, screencasts.
     Performanta: foarte scazut.

  7) Deinterlace — bwdif mode=send_field parity=auto
     OBLIGATORIU pt surse interlasate (DVD rip, TV analogic, VHS digitizat).
     parity=auto: detecteaza TFF/BFF din metadate.
     NU folosi pe surse progressive (camera/drone/telefon) — genereaza artefacte.
     Performanta: mediu.

  8) Upscale 4K (Lanczos) — scale=3840:-2:flags=lanczos
     Upscale inteligent. Nu se combina cu Resize. Pt material vechi 1080p/720p,
     drone 2.7K.

  9) Stabilizare vidstab (2-pass) — vidstabdetect + vidstabtransform
     Pass 1: detectie shakiness → .trf. Pass 2: transform + encode.
     Timp ~2x. .trf cleanup automat.
     Ideal pt drone, filmare mana, actiune.

  10) Custom — string ffmpeg manual
      Introdu orice filtru valid (ex: eq=brightness=0.05, hflip, vignette).
      Nu se face validare — sintaxa gresita opreste encode.

  COMBINATII RECOMANDATE:
    DVD/TV interlasata + denoise → custom: bwdif=mode=send_field:parity=auto,hqdn3d=4:3:6:4.5
    4K drone ISO ridicat        → Denoise light (2)
    VHS digitizat / vechi       → Denoise strong (4)


  ─── 7.9. Audio output ───

  1) AAC 192k / 5.1 384k / 7.1 768k [implicit]
     Lossy, compatibilitate maxima.
  2) AAC custom — bitrate manual (128k, 256k, 320k).
  3) Opus 128k / 5.1 256k / 7.1 512k
     Lossy, calitate superioara la bitrate mic. Container mkv/webm/mp4 (4.3+).
  4) Opus custom.
  5) FLAC lossless — zero pierdere, fisier mai mare. Doar mkv.
  6) FLAC custom — compression level 0-12 (8=default).
  7) E-AC3 (Dolby Digital Plus) — stereo 224k / 5.1 640k / 7.1 1024k
     Compatibil nativ Samsung TV + soundbar.
     NOTA: ffmpeg NU encodeaza Atmos JOC. TrueHD→E-AC3 produce surround
     bun, dar pierde obiectele spatiale. Pentru E-AC3+Atmos: Dolby
     Encoding Engine (extern, comercial).
  8) AC3 (Dolby Digital legacy) [v53] — stereo 224k / 5.1 448k (max 640k spec).
     Pentru TV-uri pre-2010 / set-top box vechi / console PS3-PS4 fara
     decoder E-AC3. AC3 nu suporta peste 5.1 canale — sursa 7.1 e
     auto-downmixed la 5.1 cu warning. Pe TV-uri moderne foloseste
     E-AC3 (mai eficient).
  9) LPCM (PCM necomprimat) — 16/24/32 bit.
     Necomprimat, calitate maxima, fisier foarte mare. Doar mkv/mov.
     Ideal pentru mastering, DaVinci Resolve.
 10) Pastreaza audio original (copy) — fara re-encode.

  In meniul 2 (encode doar audio), optiunea 10 e Eclipsa Audio (IAMF,
  AOMedia) — authoring spatial deschis din surse stereo/5.1/7.1/7.1.4
  (substream-uri Opus; doar MP4/MOV + MP4Box). Pe surse Dolby Atmos,
  obiectele pot fi REDATE pozitional in 7.1.4 prin Cavern (v89).
  Detalii → sectiunea 8.10.

  ─── 7.9.1. AV_DOWNMIX_STEREO=1 env var (v53) ───

  Forteaza downmix la 2.0 stereo pe TOATE codec-urile re-encode (AAC,
  Opus, FLAC, E-AC3, AC3, PCM). Cand sursa e 5.1/7.1, output-ul devine
  stereo cu matricea de downmix default ffmpeg.

  Bitrate target ramane stereo (NU se auto-scaleaza la 5.1/7.1). Ex:
  default AAC 192k stereo + sursa 5.1 + AV_DOWNMIX_STEREO=1 → output
  stereo 192k (in loc de 384k pentru 5.1).

  Folosire:
    bash:        AV_DOWNMIX_STEREO=1 bash av_launcher.sh
    PowerShell:  $env:AV_DOWNMIX_STEREO = "1"; .\av_encode.ps1
    Profile:     adauga AV_DOWNMIX_STEREO=1 inainte de comanda

  Use cases:
    - Output portabil / mobile / casti (mai usor de manevrat la sursa)
    - Car audio (multe sisteme moderne stereo-only sau cu downmix propriu)
    - Streaming bandwidth limited
    - Master 5.1/7.1 → versiune stereo pentru distribuit (pastreaza
      varianta surround in alta lansare)

  LOUDNORM (v23, EBU R128 2-pass):
    Meniu separat dupa Audio output. Target -24 LUFS, True Peak -2.0 dB,
    LRA 7 LU. Pass 1 analiza → Pass 2 aplicare cu linear=true.
    Nu se aplica daca audio = copy. v67: se aplica pe PRIMA pista re-encodata
    (nu fortat pe track 0) — daca pastrezi track 0 si re-encodezi altul,
    normalizarea merge pe pista potrivita.

  SELECTIE AUDIO PER-PISTA (v67, bash + PowerShell):
    Cand sursa are >1 pista audio si nu e audio copy, dialog per-fisier care
    arata lista pistelor (codec / canale / limba) si ofera:
      1) Track 0 re-encode, restul copy [implicit] — comportamentul clasic
      2) Selecteaza per pista: E=encode / C=copy / S=skip (scoate din output)
    Bitrate + downmix se calculeaza per pista (dupa canalele EI). Fisierele cu
    o singura pista nu primesc dialog (zero schimbare). Disponibil la "Encode
    video + audio" SI la "Encode doar audio".
    Bypass non-interactiv (CI):
      AV_AUDIO_TRACKS="0,2" — piste de re-encodat (restul copy); sau =all.
      AV_AUDIO_DROP="1,3" (v68) — piste de scos (skip) din output. Combinabil
        cu AV_AUDIO_TRACKS. Doar AV_AUDIO_DROP setat → track 0 encode + drop.
    Fara variabile → default (track 0 encode, restul copy).

  AVERTISMENT COMPAT CONTAINER (v68):
    Cand o pista audio PASTRATA (copy) are un codec incompatibil cu containerul
    de iesire (ex. E-AC3 / TrueHD / DTS in .mov; non-Opus in .webm), suita te
    anunta clar inainte de encode — ffmpeg ar fi esuat sau ar fi pierdut pista.
    Solutii sugerate: container MKV (accepta orice), sau re-encodeaza pista (E).
    Activ la Encode, Audio-only si Concat. Trim/Burn-in pastreaza containerul
    sursei → mereu compatibile (nu necesita avertisment).

  SURROUND AUTO-DETECT:
    >2 canale (5.1): AAC 384k, Opus 256k, E-AC3 640k.
    >6 canale (7.1): AAC 768k, Opus 512k, E-AC3 1024k.
    Custom: bitrate ramane cel introdus. v67: aplicat per pista la selectia
    per-pista (fiecare pista isi primeste bitrate-ul dupa canalele ei).

  AVERTIZARI METADATA (per fisier, in log, nu blocheaza):
    TrueHD + re-encode → pierdere metadata Atmos.
    DTS-HD MA / DTS:X + re-encode → pierdere metadata lossless/spatiala
                                    (ffmpeg nu poate encoda DTS-HD — Xperi).

  Implicit: prima pista audio se re-encodeaza; restul -c:a copy (lossless).


  ─── 7.10. Compatibilitate container (date reale ffmpeg 8.1) ───

  VIDEO ENCODERE (ce putem SCRIE):
    libx265 / libx264         → mp4, mkv, mov
    libsvtav1 / libaom-av1    → mp4, mkv, webm
    dnxhd                     → mkv, mov, mxf
    prores_ks                 → mov [implicit] / mxf (v74)
    liboapv / libopenapv      → mp4, mov, mkv (ffmpeg 8.1+ OpenAPV)

  AUDIO ENCODERE (ce putem SCRIE):
    AAC                       → mp4, mkv, mov
    Opus                      → mp4 (4.3+), mkv, webm
    FLAC                      → mp4, mkv (incompat .mov / .mxf)
    E-AC3                     → mp4, mkv (incompat .mov)
    AC3                       → mp4, mkv (incompat .mov)
    LPCM                      → mkv, mov, mxf
    Copy                      → orice container compatibil cu sursa

  MXF accepta DOAR audio PCM (necomprimat). AAC / E-AC3 / AC3 / FLAC + .mxf
  esueaza la muxare — suita ofera audio PCM sau schimbarea in .mov.

  Daca alegi combinatie incompatibila (FLAC + mov, E-AC3 + mov, LPCM + mp4,
  audio comprimat + mxf, WebM + non-Opus), scriptul ofera switch automat.

  Nota APV: Decodarea APV e inclusa in ffmpeg 8.1 standard — fisierele APV
  pot fi citite si convertite la orice alt codec. Encodarea APV functioneaza
  acum complet (vezi 7.4.1) — necesita ffmpeg 8.1+ cu OpenAPV (liboapv /
  libopenapv, detectat automat; nu e in build-ul Termux standard).


  ─── 7.11. CRF / VBR 1-pass / VBR 2-pass (v51) ───

  CRF — calitate constanta (recomandat default). Scriptul alege per rezolutie:
    x265: 4K=22 / 1080p=21 / 720p=20
    x264: 4K=20 / 1080p=19 / 720p=18
    AV1:  4K=30 / 1080p=28 / 720p=26
  Sau alegi CRF custom (0=lossless, valori mai mari = fisier mai mic).

  VBR 1-pass — bitrate mediu tinta (ex: 4000k, 4M). Maxrate=1.5x, bufsize=2x
        auto. Poti suprascrie maxrate/bufsize manual. Encoder vede fisierul
        secvential — distributia bitrate intre scene e bazata pe euristic.

  VBR 2-pass (v51) — pleaca de la acelasi target bitrate, dar encoder face
        un Pass 1 (analiza, fara audio, output null) ca sa stie unde sa
        aloce mai mult/mai putin bit-budget in Pass 2. Pe acelasi target
        kbps obtii calitate vizibil mai buna pe scene complexe (miscare,
        grain, fadeuri). Durata totala ~1.5x fata de 1-pass.
        Disponibil DOAR pe SW encoders: libx265, libx264, libsvtav1,
        libaom-av1. HW backends (NVENC/QSV/VAAPI/VT/AMF/MediaCodec) NU
        suporta 2-pass — meniul ascunde optiunea automat.

  ─── 7.11.1. VBV / Level / Tier automation (v51) ───

  Encoderul calculeaza automat nivelul minim cerut de rezolutie × framerate
  si tier-ul (HEVC Main vs High) corespunzator bitrate-ului tinta. Logica
  in suggest_vbv_for_target (av_common.sh) si Suggest-VbvForTarget (PS1).

  Tabel level minim per codec:
    HEVC: 1080p30=4.0  1080p60=4.1  4K30=5.0  4K60=5.1  4K120=5.2  8K=6.1
    H.264: 1080p=4.1   4K30=5.1     4K60+=6.0
    AV1:   1080p=4.0   4K30=5.0     4K60=5.1   8K=6.1

  Pe VBR/2-pass, daca target_kbps × 1.5 (maxrate) depaseste MaxBR-ul Main
  Tier la nivelul ales, encoderul escaladeaza automat:
    HEVC: Main → High Tier (ex: 4K30 Main=25Mbps, High=100Mbps); daca si
          High e prea mic, urca level (ex: 5.0 High → 5.1 High = 160Mbps)
    H.264: urca level direct (4.1=62.5Mbps → 5.0=168.75Mbps → 5.1=300Mbps)
    AV1:   urca level (5.0=30Mbps → 5.1=40Mbps → 5.2=60Mbps)

  HRD signaling adaugat pe VBR/2-pass:
    x265: hrd=1 (in x265-params)
    x264: nal-hrd=vbr (in x264-params, combinat cu EXTRA_X264)
    AV1:  N/A (level signaling suficient)

  Aceste setari fac stream-urile HRD-compliant (decodabile sigur pe TV-uri
  hardware care impun limite VBV stricte, ex Sony Bravia / LG OLED).

  ─── 7.11.1.4. HW VUI fix via BSF (v53 BUG FIX paralel) ───

  Acelasi bug VUI ca SW pre-v52 a fost confirmat pe HW encoders (NVENC,
  QSV, VAAPI, VideoToolbox, AMF, MediaCodec) prin field test live pe
  hevc_qsv real (Intel iGPU). Stream-urile HDR10 produse de HW aveau
  color_primaries + transfer = "unknown" identic cu SW pre-v52.

  Fix v53: bitstream filter post-encode (hevc_metadata pentru HEVC,
  av1_metadata pentru AV1, h264_metadata pentru H.264) rescrie VUI in
  SPS/OBU dupa ce HW encoder a produs frame-urile. Verificat live: HW
  output v53 produce bt2020nc/bt2020/smpte2084 corect ca SW.

  Aplicat pe TOATE 6 HW backends. Fara cost de viteza (BSF post-process
  ruleaza alaturi de muxer, nu re-encode).


  ─── 7.11.1.5. VUI color signaling (v52 BUG FIX critic) ───

  Pre-v52, toate stream-urile HDR10/HLG produse de proiect aveau VUI
  incomplet la nivel stream (color_primaries + transfer = "unknown")
  desi setam explicit BT.2020 + PQ via ffmpeg flags. Cauza: ffmpeg
  `-color_primaries bt2020 -color_trc smpte2084 -colorspace bt2020nc`
  scriu Matroska container "Colour" element care override-uia VUI-ul
  din stream. Plus consecinta tacuta: x265 dezactiva automat
  hdr10-opt cu mesajul "Recommended Settings for HDR10-opt: colour
  primaries should be BT.2020, transfer characteristics should be
  SMPTE ST.2084, Disabling hdr10-opt."

  Impact pe stream-urile vechi: HDR TV-urile care citesc VUI puteau
  sa nu intre in mod HDR10 automat; hdr10-opt (HDR10 optimization
  quality boost) era inactiv complet → calitate HDR10 suboptimala.

  Fix v52: removed ffmpeg color flags de la nivel container.
  Pastrat doar colorprim/transfer/colormatrix EXPLICIT in
  -x265-params (string: bt2020, smpte2084, arib-std-b67, bt709) si
  valori numerice in -svtav1-params (AV1 spec: color-primaries=9
  BT.2020, transfer-characteristics=16 PQ / =18 HLG, matrix-
  coefficients=9). Verificat live pe ffmpeg 8.1.1: stream produce
  `bt2020nc/bt2020/smpte2084` + Mastering display + max-cll +
  hdr10-opt ACTIV.

  Beneficiu: HDR10 streams produse de v52+ sunt complet semnalizate
  catre TV → mod HDR se activeaza correct + hdr10-opt e activ pentru
  prima data in istoria proiectului. Re-encodeaza fisierele vechi
  daca vrei sa beneficiezi de quality boost.


  ─── 7.11.2. HDR10 static metadata (v51) ───

  Aplica pe TOATE modurile (CRF, 1-pass, 2-pass) cand output-ul e HDR10.
  Encoder extrage din sursa (via ffprobe) Mastering Display + MaxCLL/MaxFALL
  si le injecteaza in stream:
    x265: master-display=G(gx,gy)B(bx,by)R(rx,ry)WP(wx,wy)L(maxL,minL):
          max-cll=MaxCLL,MaxFALL (chromaticity ×50000, luminance ×10000)
    SVT-AV1: mastering-display=G(g.x,g.y)... + content-light=N,M (float)
    libaom-av1: NU suporta — color signaling OK, dar fara master display

  Daca sursa nu raporteaza (LOG→HDR10, HLG→HDR10, DV→HDR10 cand sursa nu
  are side_data complet), foloseste defaults BT.2020 + 1000 nits peak
  (Apple/Netflix master) cu MaxCLL/MaxFALL 1000,400. Log clarity: campul
  HDR10_STATIC_SOURCE indica `probe` sau `default-*` per fisier.

  Beneficiu vizibil: player-ele HDR (Apple TV, LG OLED, Samsung QLED) fac
  tone-mapping corect pe display-uri cu peak diferit de master. Fara
  static metadata, player-ul ghiceste (1000 nits implicit) — cu metadata
  corecta, highlights nu sunt clipped/crushed.

  v63 — MaxCLL/MaxFALL masurat real (optional). Implicit, cand sursa NU are
  light-level inscris, se folosesc valorile generice 1000,400. Cu optiunea
  "Masoara real din video" (flag HDR10_MEASURE_CLL — env / camp profil /
  prompt per-fisier in dialogul HDR10-preserve si HLG → HDR10), suita face o
  trecere de analiza si scrie MaxCLL = varful real de luminozitate /
  MaxFALL = media. Util mai ales la HLG → HDR10 (HLG nu are niciodata
  light-level inscris). Mastering display ramane 1000 (descriptorul
  monitorului de gradare). Daca sursa are deja CLL inscris, acela e folosit
  (nu se masoara degeaba).
  v79 — masuratoarea e acum RGB-precisa (CTA-861.3): tine cont de cea mai
  luminoasa dintre cele trei culori (max R/G/B) in fiecare pixel, nu de luma.
  Asa highlight-urile foarte colorate (rosu/albastru saturat) nu mai sunt
  subestimate, cum erau cu masuratoarea luma-based de pana acum. Tot opt-in,
  fara costul implicit pe fiecare encodare.


  ─── 7.11.3. NVENC 2-pass quality boost (v53) ───

  NVENC suporta mod multipass intern — adevarat 2-pass intr-un singur
  encode. v53 expune asta via ENCODE_MODE=3 cand HW_BACKEND=nvenc:

    User flow:
      1) Selecteaza HW backend = NVENC
      2) La meniul "Mod encodare", apare optiunea 3 (anterior ascunsa pe HW)
      3) Alegi mode 3 → encoder activeaza automat:
           - -multipass fullres (true 2-pass intern)
           - -bf 4 (B-frames 4 vs default 3, compresie mai buna)
           - -rc-lookahead 32 (allocare bitrate inteligenta)
           - -aq-strength 10 (anti-banding scene flat areas)
           - -weighted_pred 1 (fade-uri/dizolvari) — DOAR HEVC/H.264, AV1 skip

    Cost: encode ~30-50% mai lent decat NVENC 1-pass. Tot mult mai rapid
    decat SW 2-pass (10-30x faster overall).

    Cand sa folosesti: encode-uri arhivare, master-uri pentru distribuit,
    cinematic content. NU pentru proxy / preview / live streaming.

    Mode 1 (CRF) si mode 2 (1-pass VBR) raman cu defaults conservatoare
    pentru maximum speed.


  ─── 7.12. Preset ───

  x265 / x264:  ultrafast → veryslow (9 niveluri). slow = recomandat telefon.
  SVT-AV1:      0 (veryslow) → 12 (ultrafast). 6 (medium) = recomandat.
  libaom:       cpu-used 0 (lent) → 8 (rapid). 4 = recomandat.

  Mai lent = calitate mai buna la acelasi bitrate, dar dureaza mai mult.


  ─── 7.13. Tune / Film-grain ───

  x265 / x264:  animation, grain, film, stillimage, fastdecode, sau fara.
  AV1:          film-grain synthesis 0-50.
                0   = dezactivat
                1-10  = usor (scena curata cu putin grain)
                11-20 = mediu (film 35mm tipic)
                21-50 = intens (grain vizibil, material vintage)
                SVT-AV1: -svtav1-params film-grain=N
                libaom:  -denoise-noise-level N


  ─── 7.14. Parametri extra encoder ───

  x265:    format key=value separati cu ":" — ex: rc-lookahead=40:psy-rd=1.5
  x264:    identic — ex: ref=6:bframes=5
  SVT-AV1: identic — ex: enable-overlays=1:scd=1
  libaom:  format ffmpeg standard cu spatii — ex: -enable-chroma-deltaqp 1

  Enter = sari (fara parametri extra).

  Scripturile detecteaza automat situatii speciale si afiseaza dialog
  interactiv per fisier.

  ─── 8.1. Dolby Vision ───

  HEVC (x265):
    1) Stream copy video — pastreaza DV intact, re-encodeaza doar audio.
    2) Re-encode la HDR10 — pierde layer DV, pastreaza HDR10 base.
    3) DV preserve (HEVC 8.1) — v45: re-encode + inject RPU
       Extrage RPU codec-aware (HEVC sau AV1), encode HDR10 base, inject
       RPU post-encode → DV Profile 8.1 final. Necesita dovi_tool /
       av1dovi_tool pentru codec-ul sursei.
    4) Skip fisier.

  AV1 (svtav1 / libaom):
    AV1 nu suporta DV nativ. Optiuni (v44, 3 optiuni):
    1) Converteste la HDR10 (pierde layer DV)
    2) Sari acest fisier
    3) DV Profile 10 (AV1) — re-encode + inject [conditional]
       Extract RPU sursa, encode AV1 plain, inject post-encode → DV P10.
       Apare DOAR daca av1dovi_tool e instalat SI encoder-ul e libsvtav1.

  PROFILE DOVI_PRESERVE_POLICY (v45) — bypass dialog pentru batch/CI:
    auto (default, dialog) | preserve | convert | copy | skip

  Comportament per encoder:
    HEVC (x265): toate 5 valori suportate; fallback automat la convert daca
                 policy=preserve si tool DV lipseste.
    AV1:         preserve→opt 3, convert→opt 1, skip→opt 2.
                 copy → fallback la convert cu warning ("nu e suportat pe AV1"),
                 pentru ca AV1 nu are equivalent legacy DV stream copy.


  ─── 8.2. HDR10 / SDR ───

  HDR10 sursa (x265 / AV1):
    1) Encodeaza HDR10 10-bit — pastreaza color flags BT.2020/PQ.
    2) Encodeaza SDR 10-bit (tonemap Rec.709) — zscale + Hable + bt709.
       Util pentru ecrane non-HDR.
    3) Stream copy video.
    4) Skip.

  SDR sursa (x265 / AV1):
    1) Encodeaza 10-bit SDR — yuv420p10le (anti-banding).
    2) Stream copy.
    3) Skip.

  Nota: x265 si AV1 encodeaza mereu in 10-bit (eficienta superioara).
        x264 are dialog propriu (8-bit / 10-bit / copy / skip).


  ─── 8.3. LOG format video (Apple Log / D-Log M / Samsung Log) ───

  Detectie automata: 10-bit + BT.2020 + brand din metadata ffprobe.
  Adancimea de biti se deduce si din formatul de pixel (yuv420p10le →
  10-bit) cand bits_per_raw_sample lipseste (frecvent pe HEVC 10-bit).
    Apple Log — iPhone (com.apple.quicktime.make=Apple; v85: si dupa
                encoderul pistei video "Apple ProRes", care supravietuieste
                taierii/remux-ului cu -c copy → clipul iPhone taiat inainte
                de encodare pastreaza detectia brandului)
    D-Log M   — DJI Action/Pocket
    Samsung Log — Samsung S24 Ultra (exclus daca HDR10+ / smpte2084 / HLG)
    Unknown   — 10-bit + bt2020 fara HDR, transfer necunoscut = probabil LOG

  DJI Osmo Action 6 D-Log M — detectie din djmd: pe Action 6, atat
  profilul Normal cat si D-Log M raporteaza identic bt709 in container
  (curba LOG sta doar in pixeli) → indetectabil din metadatele uzuale.
  Discriminatorul real sta in track-ul de telemetrie djmd (protobuf), pe
  care exiftool nu il expune. Suite-ul citeste djmd-ul si recunoaste
  semnatura D-Log M a modelului Action 6 → eticheteaza corect "D-Log M
  (DJI)" si ofera dialogul LOG de mai jos. Necesita ffmpeg + Python 3
  (soft-fail la "SDR" daca lipsesc). Detectia e specifica modelului
  Action 6; alte modele DJI (sau clipuri cu djmd eliminat) raporteaza
  cinstit "SDR" → forteaza manual cu FORCE LOG DETECTION (vezi mai jos).

  HLG vs LOG: un clip HLG (transfer arib-std-b67) NU e tratat ca LOG —
  e exclus din ramurile Samsung / DJI / necunoscut si gestionat ca HLG
  (vezi 8.5). Samsung Log iese cu transfer "necunoscut", HLG cu arib —
  asa se disting. (Apple Log poate raporta tot arib → ramane ambiguu
  prin natura, eticheta Apple Log se pastreaza.)

  Meniu per-file (transformarea LOG → Rec.709 cere LUT):
    Cand exista LUT(uri):
      1) Apply LUT (.cube) → 10-bit Rec.709 [implicit]
      2) Apply Creative LUT (cand creative_*.cube gasit)
      3) Preserve Log — compresie fara schimbare culori
      4) Stream copy
      5) Skip
    Cand NU exista niciun LUT:
      Mesaj cinstit: fara LUT, LOG-ul nu poate fi transformat corect.
      1) Preserve Log (pentru grading ulterior) [implicit]
      2) Stream copy
      3) Skip

  + optiune HLG (v39, doar x265/AV1 — vezi 8.5):
    "Apply LUT Log→HLG → 10-bit BT.2100" (cand hlg_*.cube gasit)

  Conversia fara LUT (Convert SDR/HDR10/HLG) a fost scoasa din dialogul
  LOG: se baza pe zscale, care nu poate liniariza un transfer
  "necunoscut" (cazul Samsung Log) → "no path between colorspaces".
  Tonemap-ul pentru surse HDR reale (PQ/HLG) ramane (transfer cunoscut).

  ETICHETARE CULOARE: la Apply LUT / Creative / Log→HLG, iesirea e
  marcata corect (Rec.709, respectiv HLG) prin DOUA mecanisme:
    1. Filtrul setparams, adaugat dupa lut3d in lantul de filtre —
       re-eticheteaza culoarea pe imagine (lut3d schimba pixelii, dar nu
       si eticheta). Necesar pentru MKV, unde playerul citeste eticheta
       din imagine, nu din fluxul video; fara el, iesirea LUT ramanea
       marcata gresit (bt2020/unknown de la sursa) in MKV.
    2. Parametrii encoderului (x265-params / x264-params:
       colorprim=bt709:transfer=bt709:colormatrix=bt709) — pentru VUI in
       fluxul video; steagurile -color_* ale ffmpeg nu propaga VUI la
       x265/x264. AV1/SVT seteaza VUI din color_params (corect deja).
  Acelasi tratament (setparams) la Burn-in si Trim/Concat. Valabil pentru
  toate containerele (MP4 / MOV / MKV).

  x264: forteaza 8-bit. Warning la Preserve Log.
  DNxHR / ProRes: auto-preserve LOG (fara dialog, mesaj informativ).

  CAUTARE LUT (.cube):
    Termux:  /storage/emulated/0/Media/Luts/
    Windows: $InputDir\Luts\ (langa script)
    Linux/macOS: $SCRIPT_DIR/Luts/

    Potrivire pe brand (v83): suita recunoaste LUT-urile atat dupa NUMELE REAL
    (asa cum sunt descarcate) cat si dupa prefixul conventional:
      Apple   → *AppleLog*.cube        (sau prefix apple_log_*.cube)
      Samsung → *Samsung*Log*.cube     (sau prefix samsung_log_*.cube)
      DJI     → *D-LogM* / *DLog*.cube (sau prefix dji_dlog_m_*.cube)
      HLG LUT → hlg_apple_log_*.cube / hlg_dji_dlog_m_*.cube etc.
      Creative→ creative_*.cube (sau in Luts/Creative/)

    Daca 1 LUT → auto-select. Daca mai multe → dialog: LUT-urile potrivite
    brandului detectat apar PRIMELE (marcate "potrivit brand", alese cu Enter),
    restul dupa — dar lista COMPLETA ramane selectabila (poti alege manual orice
    LUT, inclusiv de alt brand). Fara niciun LUT de brand → toate .cube, alfabetic.

  SURSE LUT-uri:
    Apple:   developer.apple.com → "Apple Log Profile Delivery SDK"
    DJI:     dji.com → pagina produsului → Downloads
    Samsung: developer.samsung.com → "Samsung Log to Rec709 3DLUT v1.0"

  FORCE LOG DETECTION:
    Setare globala in launcher pentru camere care nu seteaza metadata
    corect (camere chinezesti, GoPro vechi, Sony S-Log3). Forteaza
    dialog LOG pe toate fisierele. Salvat in profil.

  VFR WARNING:
    Detectie automata avg_frame_rate vs r_frame_rate. Cand sursa LOG e
    VFR (iPhone, Samsung), dialogul afiseaza warning si recomanda setare
    FPS fix din meniu.


  ─── 8.4. HDR10+ (dynamic metadata) ───

  Detectie: side_data SMPTE ST 2094-40 prezent in stream.

  Dialog cu hdr10plus_tool disponibil:
    1) Re-encode HDR10 static — pierde metadata dinamica.
    2) Re-encode HDR10+ — extract JSON via hdr10plus_tool, reinject la encode.
       x265: -x265-params dhdr10-info=<json>
       SVT-AV1: -svtav1-params hdr10plus-json=<json> (v1.5+)
       libaom-av1: NU suporta hdr10plus-json — fallback HDR10 static.
    3) Stream copy video.
    4) Triple-layer DV+HDR10+HDR10+ [doar daca si dovi_tool instalat]
       Pipeline: extract HDR10+ JSON → genereaza DV RPU Profile 8.1 CMv4.0
       → encode x265 cu dhdr10-info → inject DV RPU → re-mux.
       Rezultat: fisier cu 3 layere (DV + HDR10 + HDR10+). Cel mai
       compatibil output posibil.

  Cross-codec gate fix (v45):
    Tool-ul corect e ales pe baza codec-ului SURSEI (extract), nu target-ului.
    Pe sursa AV1 + target HEVC: mesajul de eroare numeste explicit
    "av1hdr10plus_tool" (tool-ul lipsa pt sursa AV1).
    Triple-layer inject ramane gate pe target codec (acolo se injecteaza).

  HDR10+ pe APV (v69):
    Encoderul APV pastreaza si el metadata dinamica HDR10+ (motor propriu,
    fara hdr10plus_tool — scriere per-cadru direct in fluxul APV), din
    orice sursa HDR10+ (HEVC / AV1 / APV) si inapoi. Detalii: 7.4.1.

  DOVI + HDR10+ co-existence (v45):
    Cand sursa are DV + HDR10+ embedded (Profile 8.1 hybrid), ambele
    layere sunt pastrate prin encode. RPU-ul real extras din sursa NU
    mai e supra-scris de un RPU sintetizat din JSON.

  SEMNALIZAREA DV DE CONTAINER (v70/v71/v72 — rezolvata pe MKV si MP4):
    Hibridele Dolby Vision create de suita (triple-layer / inject) au
    stratul DV COMPLET in bitstream (RPU per frame, verificabil cu
    dovi_tool / av1dovi_tool extract-rpu). Pana in v69, ffmpeg nu putea
    scrie si inregistrarea de configurare DV a containerului (DOVI config
    record / box-ul dvcC) pornind de la un bitstream brut → televizoarele
    care decid DOAR dupa semnalizarea containerului redau fisierul ca
    HDR10/HDR10+ (corect si sigur, dar fara stratul DV activ), in timp ce
    playerele PC (mpv, madVR — care citesc RPU-ul direct) activeaza DV.
    Cand uneltele de container sunt disponibile, suita scrie automat
    aceasta semnalizare → Dolby Vision se activeaza si pe televizoare:
      - HEVC pe MKV     (v70) — via mkvmerge (MKVToolNix)
      - HEVC pe MP4/MOV (v71) — via MP4Box (GPAC)
      - AV1  pe MKV     (v71) — via mkvmerge
      - AV1  pe MP4/MOV (v72) — via MP4Box (GPAC)
    Cand unealta lipseste, comportamentul ramane cel de pana acum (DV in
    flux, fara semnalizare de container), fara niciun mesaj. Instaleaza cu
    tools/mkvmerge_installer si tools/mp4box_installer (.sh pe Linux/macOS/
    Termux, .ps1 pe Windows). Semnalizarea se pastreaza si la operatiile
    fara re-encodare (remux, stream copy, taiere, doar audio; v73: si la
    unirea Concat prin stream copy si in pipeline pe variantele copy). La
    extragerea telemetriei 1:1 (embed) spre MP4 dintr-o sursa DV apare un
    avertisment (pe MP4 semnalizarea de container se pierde → pastreaza MKV,
    v73). "Verifica fisiere media" raporteaza corect profilul DV pe aceste
    hibride.
    Toate combinatiile uzuale sunt acum acoperite (HEVC si AV1, MKV si
    MP4/MOV).

  Fara hdr10plus_tool:
    1) Re-encode HDR10 static.
    2) Stream copy.


  ─── 8.5. HLG (BT.2100 HLG, v39) ───

  Al 4-lea tip de sursa HDR cu dialog dedicat (alaturi de HDR10/HDR10+/DV).

  Detectie: color_transfer=arib-std-b67. Mutual-exclusive cu HDR10/HDR10+/DV/LOG.

  Dialog HLG (5 optiuni):
    1) HLG nativ — pastreaza signaling BT.2100 HLG (recomandat).
    2) HLG → HDR10 (PQ) — zscale linearization + smpte2084.
    3) HLG → SDR (Rec.709) — zscale + tonemap=hable.
    4) Stream copy.
    5) Skip.

  HW Windows: NVENC/QSV/AV1-AMF accepta HLG p010le.
              h264_amf/hevc_amf raman 8-bit (signaling se transmite oricum).
              h264 HW: HLG→HDR10 auto-fallback la HLG nativ (no SEI HDR10).

  Pipeline + Trim & Concat: detect HDR mode "hlg" + injectare params HLG
  corect (fara hdr10=1) la Pass 3.

  v63 — HDR10 → HLG (HEVC + AV1), simetric cu HLG → HDR10. Cand sursa e HDR10
  (PQ), dialogul ofera optiunea "Converteste la HLG 10-bit (BT.2100)" pe langa
  pastrare HDR10 / tonemap SDR. Filtru oglinda (doar transfer-ul difera):
  zscale PQ → linear → HLG (arib-std-b67). HLG e metadata-free → fara hdr10=1 /
  master-display / max-cll; VUI derivat din color params (x265 transfer=
  arib-std-b67, svtav1 transfer 18). Doar x265 / AV1 (x264 e 8-bit, fara HDR).
  Util: HLG se reda gratios si pe ecrane SDR (backward-compatible) + e prietenos
  cu telefoanele / broadcast-ul.


  ─── 8.6. DJI tracks (GPS nativ) ───

  Detectie: codec tags djmd (GPS / telemetrie), dbgi (debug), tmcd
  (timecode), cover JPEG.

  Track-urile de date DJI au codec "none" — ffmpeg NU le poate pune in
  niciun container (nici mp4/mov, nici mkv). Prin urmare sunt eliminate
  mereu la encodare. GPS-ul nativ se pastreaza in schimb prin re-adaugare
  dupa encodare (v78):

    Pe MP4 / MOV: pista GPS (djmd) e re-adaugata automat peste fisierul
      encodat, prin MP4Box — traseul GPS ramane intact, fara pasi manuali.
      Functioneaza pe encodare completa, pe copierea rapida (video 1:1) si
      pe encodarea doar-audio. Pista voluminoasa de debug (dbgi) e lasata
      deoparte — nu aduce nimic util si ar umfla fisierul.

    Pe MKV (sau alt container): pastrarea nativa nu e posibila. Foloseste
      meniul Telemetrie → "Embed lossless" pentru a pastra GPS-ul ca
      subtitrare / date, sau pastreaza output-ul pe MP4/MOV.

  Setare (profil): DJI_PRESERVE_META = auto (implicit — intreaba per fisier)
  / on (mereu pastreaza, fara intrebare) / off (niciodata). In rulare
  automata / fara terminal interactiv, "auto" pastreaza GPS-ul (alegere
  sigura). Necesita MP4Box (installer in tools/).

  Cover JPEG (thumbnail DJI) NU se copiaza niciodata — ar cauza re-encode
  MJPEG→libx265 (codec conflict).


  ─── 8.7. Subtitrari PGS / DVDSUB + container MP4/MOV ───

  PGS si DVDSUB sunt formate imagine — incompatibile cu mov_text.
  Scriptul le omite automat (-sn) cu avertisment.
  Solutie: foloseste mkv pentru a pastra subtitrari PGS/DVDSUB.


  ─── 8.8. Interactive Mode ───

  Activabil din meniu launcher ("Normal / Dry-run / Interactiv") sau profil.
  Dupa fiecare fisier encodat cu succes apare dialog:
    1) Pastreaza setarile (continua) [implicit]
    2) Modifica setari — audio / CRF / normalizare / filtru
    3) Opreste batch-ul

  Util pentru batch-uri mixte (drone + anime + film = setari diferite).
  Nu apare la ultimul fisier. Nu apare in dry-run.


  ─── 8.9. Audio spatial — Dolby Atmos / DTS:X (v87) ───

  Formatele cu obiecte spatiale — Dolby Atmos (E-AC-3 JOC / TrueHD) si
  DTS:X (peste DTS-HD MA) — NU pot fi create sau re-encodate cu unelte
  libere: encoderele exista doar la Dolby / DTS (licentiate). Obiectele
  traiesc in bitstream si supravietuiesc DOAR la copierea 1:1 a pistei;
  o re-encodare le pierde definitiv, iar fisierul rezultat arata la fel
  ("eac3") — pierdere invizibila.

  Suita detecteaza automat pistele Atmos / DTS:X (validat pe tonurile
  oficiale Dolby si DTS Sound Check) si:

    - la encodare (meniul 1) si audio-only (meniul 2), cand o pista
      spatiala urmeaza sa fie re-encodata, apare garda:
        1) Copiaza pista 1:1 — pastreaza obiectele  [implicit]
        2) Re-encodeaza cum ai ales — pierde obiectele
      Pistele sunt marcate "← ATMOS" / "← DTS:X" in dialogul de
      selectie per-pista.
    - "Verifica media" eticheteaza pistele: eac3 (Atmos), dts (DTS:X).
    - Demux marcheaza pistele spatiale; Remux avertizeaza explicit cand
      o pista incompatibila cu containerul tinta e spatiala ("foloseste
      MKV ca s-o pastrezi").
    - Trim & Concat avertizeaza inainte de alegerea audio (la Concat
      optiunea implicita e re-encodare AAC → alege "copy").

  Bypass non-interactiv (CI / batch):
    AV_ATMOS_POLICY=copy|reencode
    AV_DTSX_POLICY=copy|reencode
  Fara env, rularile non-interactive aleg COPY (nu se pierde nimic
  tacut).

  SEMNALIZARE DE CONTAINER (MP4/MOV): FFmpeg nu scrie extensia Atmos
  in metadata containerului MP4 — playerele care decid dupa container
  (ecosistemul Apple) nu ar activa Atmos, desi pista il contine. Cand
  MP4Box (GPAC) e instalat (vezi tools/mp4box_installer), suita
  re-scrie semnalizarea automat oriunde o pista E-AC-3 Atmos e copiata
  intr-un MP4/MOV (encode / stream copy / audio-only / Trim & Concat
  pe caile de copiere / Remux / Mux). Optional si silentios cand
  lipseste — bitstream-ul ramane oricum intact, iar TV-urile si
  playerele care citesc bitstream-ul vad Atmos si fara semnalizare.
  Pe MKV nu e nevoie de nimic.

  Nota Auro-3D: isi ascunde canalele de inaltime in bitii de sub
  pragul audibil ai unei piste 5.1 normale (PCM / DTS-HD MA) —
  nedetectabil fara decoderul licentiat. Copierea 1:1 il pastreaza;
  orice re-encodare sau procesare audio (normalizare, downmix) il
  pierde.


  ─── 8.10. Eclipsa Audio (IAMF) — creare si pastrare (v88; 7.1.4 +
             Atmos → Eclipsa in v89) ───

  Eclipsa Audio e formatul de audio spatial DESCHIS al AOMedia (IAMF —
  Immersive Audio Model and Formats; royalty-free, spre deosebire de
  Atmos / DTS:X), promovat de Samsung si Google pe TV-urile si
  telefoanele recente. IAMF nu e un codec: e un GRUP de substream-uri
  Opus + metadata de scena (Audio Element + Mix Presentation) care
  traieste in container. IAMF exista DOAR in MP4/MOV — Matroska/WebM
  nu au inca mapare (nici FFmpeg, nici mkvmerge).

  CREARE (authoring) — meniul 2 (encode doar audio), optiunea 10:
    - surse stereo / 5.1 / 7.1 / 7.1.4 (12 canale, v89) → IAMF cu
      layere scalabile (stereo de baza + stratul complet; pe 7.1.4,
      7 substream-uri: 5 perechi stereo + centru + LFE), Opus 256k;
      video-ul (daca exista) e copiat 1:1 pe langa — inclusiv
      semnalizarea Dolby Vision, subtitrarile (pe surse MP4/MOV; pe
      alte containere nota onesta), capitolele si GPS-ul nativ DJI.
    - cere container MP4/MOV (pe altul, oferta de schimbare) si
      MP4Box/GPAC instalat (vezi tools/mp4box_installer) — FFmpeg
      construieste structura IAMF nativ dar NU o poate scrie in
      container.
    - surse cu alt numar de canale decat 2/6/8/12 (sau fara audio)
      → skip onest; sursa DTS:X → avertisment onest (obiectele NU
      se transfera — intra doar bed-ul).
    - optiunea 10 pe o sursa DEJA-IAMF nu re-encodeaza: copy 1:1 +
      re-scrierea grupului (fara downgrade tacut) — pastreaza
      subtitrarile, attachments, capitolele, semnalizarea Dolby
      Vision si GPS-ul nativ DJI, ca fluxul normal al meniului.

  ATMOS → ECLIPSA 7.1.4 (v89): pe sursele Dolby Atmos (E-AC-3 JOC
  sau TrueHD), obiectele pot fi REDATE pozitional in canale 7.1.4
  prin Cavern (VoidXH) — singurul renderer liber care decodeaza
  obiectele Atmos (TrueHD prin truehdd, descarcat automat de
  Cavernize la prima rulare). Optiunea 10 ofera atunci:
    1) Render 7.1.4 → Eclipsa cu canale de inaltime [implicit cand
       Cavernize e instalat] — obiectele intra in IAMF
    2) Doar bed-ul de canale (comportamentul clasic)
    3) Sari fisierul
  Video/subtitrari/capitole/GPS DJI raman din sursa; audio-ul vine
  din WAV-ul 7.1.4 randat. Pentru batch: AV_ATMOS_ECLIPSA_POLICY=
  render|bed|skip (non-interactiv fara env → bed). Render esuat →
  fallback onest pe bed. Cere Cavernize (tools/cavernize_installer;
  Windows validat, macOS ghid manual, Linux/Termux indisponibil —
  fara el totul ramane ca in v88) + .NET Desktop Runtime 8+ (pe
  9/10 suita seteaza automat roll-forward). Nota: renderul WAV
  intermediar are limita RIFF 4GiB (~62 min la 12ch/48k/16-bit) →
  pe fisiere mai lungi, esec onest cu fallback pe bed. DTS:X ramane
  doar-bed (nu exista decoder liber).

  PASTRARE (passthrough): FFmpeg APLATIZEAZA grupul IAMF la piste
  Opus simple la ORICE mux sau copiere — comanda reuseste, pierderea
  e tacuta (perechea audio a semnalizarii DV v70-v72 / Atmos v87).
  Pe caile cu timeline 1:1 — encode video cu audio copy, stream copy,
  audio-only, Remux — suita re-scrie automat grupul in containerul de
  iesire direct din sursa (extractie raw prin MP4Box, byte-identica).
  In dialogul audio, substream-urile unui grup IAMF se trateaza ca UN
  unit: copy atomic, fara selectie per-pista, fara loudnorm.

  Vizibilitate: "Verifica media" eticheteaza pista "(Eclipsa)" si
  numara corect substream-urile (ffprobe le listeaza dublu pe
  IAMF-in-MP4 — suita deduplica peste tot: Remux/Demux, analiza
  per-pista, avertismente); Remux noteaza inline ca pistele opus
  formeaza un grup atomic (si avertizeaza pe tinte non-MP4/MOV);
  Trim & Concat avertizeaza ca editarea timeline-ului aplatizeaza
  grupul (substream-urile taiate nu se pot regrupa — foloseste
  encode per-clip + Remux daca ai nevoie de taieturi cu Eclipsa
  pastrat); Burn-in (v90) RE-SCRIE automat grupul pe output-ul
  complet MP4/MOV (audio-ul copiat e timeline-1:1) — pe preview-uri
  (clip taiat) si pe alte containere ramane aplatizat, cu nota
  onesta in dialog.

9. TRIM & CONCAT PIPELINE (v36/v37 + v60 HDR/LOG — meniu principal opt 6)
═══════════════════════════════════════════════════════════════

  Submeniu cu 5 optiuni:
    1) Trim (un fisier)
    2) Concat (multe fisiere)
    3) Pipeline (trim + concat + encode in 3 pass-uri)
    4) Batch trim (aceleasi cuturi pe N fisiere)
    5) Inapoi

  La intrare in submeniu: scan foldere reziduale din Temp/. Daca exista
  trim_*/concat_*/pipeline_*/preview_* vechi, dialog cu 3 optiuni:
    1) Pastreaza toate
    2) Sterge >24h [default]
    3) Sterge toate

  TIME PARSER FLEXIBIL: 45 / 1:30 / 1:05:30 / HH:MM:SS — toate acceptate.
  RANGE SELECTION: all / 1,3,5 / 1-5 / 1-3,7,10-12.


  ─── 9.1. Trim un fisier ───

  Multi-cut loop: tai oricate segmente intr-o sesiune.
  Pentru fiecare segment:
    - Start / end (format flexibil)
    - Confirmare
    - Precizie:
      1) Stream copy (instant, lossless, ±1-2s la keyframe) [default]
      2) Re-encode (exact, frame-accurate, mai lent)
    - Re-encode: codec (x265/x264) + CRF + audio (copy/aac/eac3)
    - v60: la re-encode pe sursa non-SDR → dialog HDR/LOG (vezi 9.5)
  Output: <nume>_trim<N>_<start>.<ext> cu collision auto-increment.


  ─── 9.2. Concat clips ───

  Sort: nume / data / dimensiune / manual / pastreaza selectia.
  Container: mkv [default] / mp4 / mov.

  Signature check (ffprobe codec + rez + fps + pix_fmt per fisier):
    Toate identice → optiune stream copy (concat demuxer, instant, lossless)
                     sau re-encode (compresie suplimentara).
    Diferente      → re-encode OBLIGATORIU via concat filter.

  NOTA VFR (v86): taieturile din acelasi clip cu frame-rate VARIABIL
  (VFR — tipic telefoane si camere de actiune) raporteaza fps diferit
  intre ele, deci pica pe "Diferente" → re-encode. E corect, nu e
  defect: unirea fara re-encode pe taieturi VFR produce timestamps
  corupte la punctele de lipire (sacadare vizibila la jonctiuni).
  Mesajul explica acum explicit cazul VFR in loc de genericul
  "codec/rez/fps diferit". Sursele cu frame-rate constant (CFR) se
  unesc in continuare instant, lossless, prin concat demuxer.


  ─── 9.3. Pipeline (trim + concat + encode) ───

  Pas 1: Selectie fisiere + sort.
  Pas 2: Indicare care fisiere au nevoie de trim.
  Pas 3: Setari encode GLOBALE:
    - Mod encode (v37): Video+Audio re-encode [default] / Audio-only (video copy)
    - Codec (daca nu audio-only): libx265 [default] / libx264 / libsvtav1
    - CRF (default 22)
    - Preset: medium [default] / slow / fast
    - Audio: aac 192k [default] / eac3 224k / copy
  Pas 4: Nume output + container (mkv/mp4/mov).
         Capitole automate (v37, opt-in): 1 capitol per segment via FFMETADATA1.
  Pas 5: Rezumat pre-executie:
    - Lista [FULL] / [TRIM xN]
    - Durata finala estimata
    - Temp estimat
    - Setari encode
    - Info HDR daca e cazul (auto-detect inainte de Pass 3)
    - Preview thumbnails (v37, opt-in): 3-frame tile 320p per fisier
    - Confirm

  Mod dry-run (v63): la intrarea in pipeline poti alege "2-Dry-run". Dupa
  configurarea completa (fisiere / taieturi / codec / container), suita
  afiseaza planul pe 3 pass-uri + modul HDR detectat, dar NU executa nimic —
  zero fisiere, zero foldere temp. Guard plasat dupa rezumatul de la Pas 5,
  inainte de crearea subdir-ului temp. Bypass non-interactiv: env DRY_RUN.
  Doar pipeline-ul are dry-run (Trim / Concat / Batch sunt single-step,
  majoritar stream-copy).

  Pas 6: Executie in 3 pass-uri:
    [Pass 1/3] Trim stream copy → subdir temp.
               Fisierele FULL (fara trim) NU se copiaza (referinta directa).
    [Pass 2/3] Compat check pe fisierele generate.
               Compat → concat demuxer. Diferite → switch automat la filter.
               Smart stream copy (v37): daca codec source == target,
               opt-in skip re-encode total (instant -c copy).
    Pre-Pass 3: chapters.txt + HDR mode detection (sdr / hdr10 / hdr10plus /
               hlg / dv / mixed).
               v60: codec-aware (libx265 SI libsvtav1):
                 hdr10/hlg → 10-bit + color flags + params dedicati
                   (x265: hdr10=1/hdr-opt; svtav1: enable-hdr + transfer 16/18).
                 HDR10 static (v60): master-display + max-cll injectate pe ambele
                   (x265 master-display=, svtav1 mastering-display=/content-light=).
                 hdr10plus → x265 dhdr10-info (hdr10plus_tool); svtav1 inline
                   hdr10plus-json cand build-ul SVT suporta; altfel HDR10 static.
                 dv → fallback HDR10 + warning (RPU nu se pastreaza la re-encode;
                      pentru DV pastreaza HDR10+ si transforma in HDR/DV tools opt 8).
                 mixed → no inject + warning.
                 codec libx264/libaom → no inject + warning.
               v60: sursa LOG dar agregat SDR → nota onesta (fara transform).
               v60: codec_tag (hvc1/av01/avc1) pe output MP4/MOV.
    [Pass 3/3] Concat + Encode intr-un singur ffmpeg cu progress bar real.
  Pas 7: Cleanup temp daca output OK, pastrat daca esuat.


  ─── 9.4. Batch trim (v37) ───

  N cuturi comune aplicate la TOATE fisierele selectate.
  Mod: stream copy (default, instant) sau re-encode (codec/CRF/audio).
  Skip automat fisiere mai scurte decat end_s. Sumar OK/FAIL/SKIP.
  Util pentru scoatere intro/outro din toate clipurile dintr-o sedinta
  cu un singur set de cuts.


  ─── 9.5. HDR/LOG awareness la re-encode (v60 + v62 + v73) ───

  La re-encode (NU stream copy) pe Trim / Batch trim / Concat, daca sursa
  e non-SDR → dialog inainte de ffmpeg (per-fisier la Trim/Batch, agregat
  la Concat). Reutilizeaza detectia din encode-ul principal.

  v73: clipurile LOG (D-Log M / Samsung Log / Apple Log) sunt recunoscute
  acum si la Concat (agregat). Inainte treceau tacut ca SDR si erau
  re-encodate fara LUT — imaginea iesea spalacita. Cand toate clipurile
  sunt de acelasi brand si exista un LUT potrivit in Luts/, e propus
  automat (Apply LUT / Keep LOG / Skip); la branduri amestecate, lipsa
  LUT-ului sau amestec LOG+SDR → Keep LOG / Skip + nota cu pasii corecti.

  Clasificare sursa + optiuni:
    HDR10 / HDR10+   → 1) Preserve HDR10 (10-bit + master-display + max-cll)
                          [HDR10+ cade pe HDR10 base — x265/x264 nu fac dinamic]
                       2) Tonemap → SDR (Hable)   3) Skip
    HLG              → 1) Preserve HLG (10-bit + arib-std-b67)
                       2) Tonemap → SDR           3) Skip
    LOG (apple/dji/  → cu LUT in Luts/: 1) Apply LUT Rec.709  2) Keep LOG  3) Skip
        samsung)        fara LUT:        1) Keep LOG  2) Skip
                        (v62: tonemap eliminat pe LOG — Log→Rec.709 cere LUT,
                         zscale nu poate liniariza un transfer necunoscut)
    DV               → REFUZ preserve (RPU se pierde la re-encode) →
                       doar Tonemap / Skip
    SDR              → fara dialog (flow original)

  x264 + HDR → auto-tonemap cu warning (8-bit standard nu suporta 10-bit HDR).
  codec_tag (hvc1/av01/avc1) aplicat pe output MP4/MOV/M4V.

  Bypass non-interactiv (CI/batch): TC_HDR_POLICY = preserve | tonemap |
  skip | lut — sare dialogul cu policy uniformizat.


  ─── 9.6. Folder temp ($AV_TEMP_DIR) ───

  Termux:        /storage/emulated/0/Media/Temp
  Linux/macOS:   $SCRIPT_DIR/Temp
  Windows:       <folder script>\Temp

  Lazy-creat (nu in repo). Exclus din git. Subfoldere per-rulare:
  trim_PID_ts / concat_PID_ts / pipeline_PID_ts / preview_PID_ts.
  Cleanup automat la succes, pastrate daca output esuat (pentru recovery).

  v88: Remux pe surse Eclipsa/IAMF — FFmpeg aplatizeaza grupul IAMF la
  Opus simplu la orice remux, deci pe tinta MP4/MOV suita re-scrie
  grupul INTREG din sursa la final (substream-urile sunt atomice —
  selectia partiala nu are sens, nota apare inline la selectia audio);
  pe tinte non-MP4/MOV avertisment onest (nu exista mapare IAMF).

  ─── 10.1. Formate suportate (input — comune remux + demux) ───

  Input (10):
    mkv, webm, mp4, m4v, mov, ts, m2ts, mts, vob, mxf

  Acopera:

  Output remux (4):

    mp4  - distribute / web / mobile

  PARTEA A — REMUX CONTAINER (sub-opt 1)
  ═══════════════════════════════════════════════════════════════

  ─── 10.2. Remux: flux complet ───

    1. Scan: OutputVideos/ + InputVideos/ pentru extensiile suportate
       (exclude *_remux pentru a evita re-procesarea)
    2. Selectie fisiere (index unic / lista / interval / ALL)
    3. Pick container tinta (o data pentru tot batch-ul)
    4. Per fisier:
       a) ffprobe enumerate: video + audio + subtitle + attachments + chapters
       b) Display tabular pe categorii cu warn-uri incompat per stream
       c) 5 prompt-uri selectie:
          - Video (auto-select daca e unic)
          - Audio (index/lista/ALL/NONE)
          - Subtitle (index/lista/ALL/NONE; convert mov_text marcat cu →)
          - Attachments (D/n — doar MKV preserva)
          - Chapters (D/n)
       d) Pre-flight: 0=ok / 1=warn (continue) / 2=fail (abort)
       e) Build ffmpeg cu -map 0:v:N + -map 0:a:N + -map 0:s:N (drop sarit)
       f) Run cu progress + tag:v (hvc1/av01/avc1) + faststart (mp4/mov)
    5. Output: OutputVideos/<name>_remux.<ext>
    6. Batch summary: Total / OK / Skip / Fail

  ─── 10.3. Sintaxa selectie (comuna remux + demux) ───

    Pentru toate prompt-urile stream:
      1            - un singur index
      1,3,5        - lista
      1-3          - interval
      1,3-5        - combinat
      ALL          - selecteaza toate (implicit, daca dai Enter)
      NONE         - elimina toate (dezactivat pentru video pe remux)

  ─── 10.4. Remux: compat matrix per target container ───

    Per stream, dispatcher `remux_stream_compat(codec, type, target)`:
      "copy"             - stream pastrat unchanged
      "convert:mov_text" - subtitrare text convertita (srt/ass → mov_text)
      "drop"             - stream incompatibil cu container-ul tinta

    MKV: permisiv — totul OK, atasamente preservate.

    MP4:
      Video: hevc, h264, av1, mpeg4, mpeg2video, vp9, prores
      Audio: aac, ac3, eac3, mp3, opus, alac, flac
      Sub:   mov_text, tx3g (text → convert; bitmap → drop)
      Drop:  attachments (font/imagine), DJI djmd/dbgi
      Audio strip: TrueHD, DTS-HD, PCM_S24LE/S16BE (lossless mari)

    MOV:
      Video: hevc, h264, prores, dnxhd, dnxhr, mpeg4, mjpeg
      Audio: aac, ac3, mp3, alac, pcm_s16be/s24be/s16le/s24le
      Sub:   mov_text (text → convert; bitmap → drop)
      ABORT: eac3 (incompat container-level — preflight level 2)
      Drop:  opus, truehd, dts, attachments

    WEBM (cel mai restrictiv):
      Video: vp8, vp9, av1 (orice altceva → preflight FAIL abort)
      Audio: opus, vorbis (orice altceva → drop)
      Sub:   webvtt (orice altceva → drop)
      Drop:  attachments

  ─── 10.5. Remux: pre-flight nivele ───

    Level 0 (ok)    - niciun warning, continui silent
    Level 1 (warn)  - cazuri "lossy compat" (strip sub/audio/attach),
                      afiseaza warn-uri si continui automat
    Level 2 (fail)  - incompatibilitate hard (eac3+mov, video non-VP/AV1+webm,
                      container necunoscut) → abort fisier

  ─── 10.6. Remux: cazuri practice ───

    1) MKV Blu-ray remux (filme) → MP4 pentru iPad/iPhone:
         hevc + truehd 5.1 + eng/ro subs + 24 fonts → MP4
         Selectezi: video 1, audio 1 (eng dub) sau 2 (ro dub),
                    sub 2 (ro) → convert mov_text
         Attachments: strip (24 fonts → drop, MP4 nu suporta)
         Output: file_remux.mp4 cu tag:v hvc1 + faststart

    2) MTS de pe Sony cam → MP4 pentru editor:
         m2ts container + h264 + ac3 + djmd track
         Selectezi: video 1, audio 1, sub NONE
         DJI track: strip (incompat MP4) — preflight level 1 warn
         Output: file_remux.mp4

    3) MKV → WEBM pentru web (gating strict):
         Daca video e hevc → preflight FAIL (WEBM doar VP8/VP9/AV1)
         Daca video e av1 → audio re-routing: eac3/aac → drop
                          → trebuie sa ai stream opus/vorbis pentru audio

    4) Subtitle-only swap:
         Acelasi container, pastrezi tot, dezbifezi sub-urile pe care
         nu le vrei. Output: <name>_remux.mkv

  ─── 10.7. Remux: limitari cunoscute ───

    - VOB multi-chunk (VIDEO_TS/VTS_01_1.VOB + VTS_01_2.VOB ...) trebuie
      concatenate intai via Trim & Concat (flow demuxer); apoi pe rezultat
      faci remux.
    - Pure remux = no re-encode. Daca un stream e incompatibil cu target-ul
      si NU exista un fallback "copy" sau "convert", el e drop-uit. Pentru
      conversie audio (ex. eac3 → ac3 pentru MOV), foloseste meniul Encode
      principal cu audio-only.
    - Sintaxa range (`1-3`) pe selectie acopera doar consecutive; pentru
      lista non-consecutiva ("1,3,5") foloseste virgula.

  PARTEA B — DEMUX STREAMS (sub-opt 2)
  ═══════════════════════════════════════════════════════════════

  ─── 10.8. Demux: strategie smart per-codec uniform wrapping ───

  Demux NU dezambaleaza la bitstream pur (.hevc, .h264, .ac3) — in schimb
  fiecare stream e wrapped intr-un container minimal care pastreaza toate
  metadata + signaling-ul, lossless. Avantajul: poti reasambla curat in
  mkvtoolnix, ffmpeg, sau MKVToolNix GUI fara pierdere.

  Strategie:
    Video    → `.mkv`  (pastreaza HDR10/HDR10+/DV RPU/timecode/color metadata)
    Audio    → `.mka`  (Matroska audio; pastreaza Atmos / E-AC3 obj data /
                        TrueHD metadata + tag-uri container language/title)
    Subtitle → ext nativ + lang suffix:
                  subrip      → .srt
                  ass/ssa     → .ass
                  webvtt      → .vtt
                  PGS         → .sup        (Bluray, bitmap)
                  dvd_subtitle→ .sub        (DVD VobSub, bitmap)
                  mov_text/tx3g → .srt      (auto-convert text)
    Cover    → ext nativ pentru attached_pic disposition:
                  mjpeg/jpeg  → .jpg
                  png/webp/bmp → .png/.webp/.bmp
    Chapters → `<name>_chapters.xml` (Matroska XML format — DOCTYPE +
               EditionEntry + ChapterAtom; import direct in mkvtoolnix)
    Attach   → folder `<name>_attach/` (fonts, imagini)
    Data     → folder `<name>_data/` opt-in (DJI djmd/dbgi, timecode
               binary) — pentru parsing real GPS/gauges foloseste opt 4
               Telemetrie din meniul principal

  ─── 10.9. Demux: output naming ───

    Video:     <name>_v<idx>_<codec>.mkv
                 ex: clip_v0_hevc.mkv
    Audio:     <name>_a<idx>_<codec>_<lang>.mka
                 ex: movie_a0_eac3_eng.mka, movie_a1_dts_ro.mka
    Subtitle:  <name>_s<idx>_<codec>_<lang>.<ext>
                 ex: movie_s0_subrip_eng.srt, movie_s1_pgs_ro.sup
    Cover:     <name>_cover_<idx>.<ext>
                 ex: movie_cover_0.jpg
    Chapters:  <name>_chapters.xml
    Folders:   <name>_attach/  +  <name>_data/

  Toate output-urile sunt in OutputVideos/. Sursa neatinsa.

  ─── 10.10. Demux: flux complet ───

    1. Scan: OutputVideos/ + InputVideos/ (exclude *_remux, *_v*_*, *_a*_*,
       *_s*_*, *_cover_*)
    2. Selectie fisiere (index unic / lista / interval / ALL)
    3. Per fisier:
       a) ffprobe enumerate: video + audio + subtitle + cover + data +
          attachments + chapters
       b) Display tabular pe categorii
       c) Prompt-uri selectie per categorie (sintaxa identica cu remux)
       d) Toggle opt-in pentru data streams + warning catre Telemetrie
       e) Extract -c copy per stream cu wrapper container corespunzator
       f) Chapters: ffprobe show_chapters JSON → Matroska XML (awk in bash,
          ConvertFrom-Json + InvariantCulture in PS1)
       g) Attachments: ffmpeg -dump_attachment cu cwd in <name>_attach/
    4. Batch summary: Total / OK / Skip / Fail (per-fisier rollup)

  ─── 10.11. Demux: cazuri practice ───

    1) Bluray MKV cu multi-audio + multi-sub → arhivare individuala:
         Selectezi: video ALL, audio ALL, sub ALL, cover ALL, chapters Y
         Output: movie_v0_hevc.mkv + movie_a0_truehd_eng.mka +
                 movie_a1_dts_ro.mka + movie_s0_subrip_eng.srt +
                 movie_s1_pgs_ro.sup + movie_chapters.xml
         Reasamblare ulterioara in mkvtoolnix GUI sau via:
           ffmpeg -i video.mkv -i audio.mka -i sub.srt -i chapters.xml \
                  -map 0 -map 1 -map 2 -c copy out.mkv

    2) DJI MP4 cu telemetrie + cover → separare:
         video (hevc) + audio (aac) + djmd track + cover
         Selectezi: video 1, audio 1, data Y (opt-in)
         Output: clip_v0_hevc.mkv + clip_a0_aac_und.mka + clip_data/
         Nota: pentru parsing real GPS, foloseste opt 4 Telemetrie

    3) Recoltare cover art din audio file:
         Album MKA cu cover embedded
         Selectezi doar cover (Y), restul N
         Output: album_cover_0.jpg

  ─── 10.12. Demux: limitari cunoscute ───

    - Wrapping in MKV/MKA NU schimba codec-ul; daca tinta finala e MP4
      pentru un device specific, foloseste apoi sub-opt 1 (Remux) pe
      output-urile demux pentru re-pack final.
    - Bitmap subs (PGS .sup, VobSub .sub) raman in formatul lor — pentru
      OCR text foloseste tool extern (Subtitle Edit, SubExtractor).
    - Data streams raman binare opaque; parsing-ul GPS/gauges se face in
      opt 4 Telemetrie (DJI/GoPro/Sony/Garmin/QuickTime).


  ─── PARTEA C: MUX (v50 — sub-opt 3) ─────────────────────────

  Combina un fisier video + N audio + N subtitrari + chapters
  + attachments intr-un container nou. Operatie 100% lossless
  (-c copy). Manual selection only — user picks fiecare track
  prin index, fara auto-grouping by basename (decisie design:
  previne mux gresite cu fisiere mismatched).


  ─── 10.13. Mux: cazuri tipice ───

    - Ai folosit demux (sub-opt 2) sa extragi streams si vrei sa
      re-combini totul intr-un container nou (eventual cu subset
      sau cu ordine schimbata).
    - Ai un raw stream HEVC (.hevc / .265) + un E-AC3 si vrei
      sa le pui intr-un MKV.
    - Adaugi o subtitrare externa (.srt / .ass) la un video deja
      encodat fara re-encode video.
    - Inlocuiesti track-ul audio dintr-un MKV (demux → editeaza
      audio extern → mux).


  ─── 10.14. Mux: extensii input acceptate ───

    Video:    mkv webm mp4 m4v mov ts m2ts mts vob mxf
              hevc h265 h264 265 264 av1 ivf vp9
    Audio:    mka m4a eac3 ac3 aac flac opus mp3 wav oga ogg
    Subtitle: srt ass ssa vtt sup idx
    Chapters: xml (Matroska) | txt (FFMETADATA1)
    Attach:   ttf otf ttc png jpg jpeg webp bmp

  Source unic: doar InputVideos (mutati fisierele acolo inainte
  de a porni Mux). Excludem OutputVideos pentru a evita mux
  accidental peste artefacte vechi.


  ─── 10.15. Mux: flux complet ───

    Pas 1: VIDEO (mandatory, single)
      Listeaza video files din InputVideos. User picks index 1-N.

    Pas 2: AUDIO (optional, multi)
      Listeaza audio files. Sintaxa: "1,3,2" → ordinea introdusa
      = ordinea track-urilor in output. "NONE" sau enter gol = skip.

    Pas 3: SUBTITRARI (optional, multi)
      VobSub pair handling: .idx + .sub combinati automat — .sub
      orfan filtrat din lista daca .idx pereche exista.

    Pas 4: CHAPTERS (optional, single)
      Acceptat Matroska XML (recomandat din Demux sub-opt 2) si
      FFMETADATA1 txt. ffmpeg face conversie best-effort la
      formatul container target.

    Pas 5: ATTACHMENTS (optional, multi)
      Fonturi (ttf/otf/ttc) si imagini (png/jpg/webp/bmp) doar
      pe MKV. Pe mp4/mov/webm → ignorat cu warning.

    Pas 6: Container target (mkv/mp4/mov/webm)
      Default mkv. Per-stream compat check (matricea Remux):
        - video incompat → abort
        - audio/sub incompat → WARN si skip pe tracks individuale
        - text subs pe mp4/mov → auto-convert mov_text
        - bitmap subs (PGS/VobSub) pe mp4/mov/webm → skip

    Pas 7: Per-track metadata (opt-in)
      Prompt unic "Editezi metadata per-track? (d/N)":
        - default automate: language din suffix .eng/_ron
          (regex [a-z]{2,3}, exclude mkv/mp4/aac/hd/sd/hq/lq),
          title gol, first audio default=yes, subs forced=no
        - daca D, walks prin fiecare audio + sub editabil
          (language, title, default flag, forced flag pt subs)

    Pas 8: Output
      <video_basename>_mux.<ext> in OutputVideos.
      Adaugat in scan exclude (preventie reprocessing).


  ─── 10.16. Mux: per-stream compat (text subs auto-convert) ───

  Matricea de compat e reutilizata din Remux (remux_stream_compat
  / Get-RemuxStreamCompat). Reguli identice:

    MKV       = permisiv (totul OK, attachments suportate)
    MP4       = hevc/h264/av1 video + aac/eac3/ac3/mp3/opus audio
                text subs → mov_text, bitmap → drop, attach → drop
    MOV       = hevc/h264/prores video + aac/ac3/alac/pcm audio
                eac3 → drop, text → mov_text, bitmap → drop
    WEBM      = vp8/vp9/av1 + opus/vorbis + webvtt (cea mai
                restrictiva tinta)


  ─── 10.17. Mux: cazuri practice ───

  A) Inlocuire track audio:
       1. Demux pe original.mkv → original_a0_eac3_eng.mka extras
       2. Edit audio extern (Audacity, ffmpeg) → original_new.mka
       3. Mux: video = original.mkv, audio = original_new.mka, subs/
          chapters/attach lasate goale → Output: original_mux.mkv

  B) Adaugare subs SRT la video encodat:
       1. Pune movie.mkv si movie.eng.srt in InputVideos
       2. Mux: video = movie.mkv, audio NONE, subs = movie.eng.srt,
          target = mkv → Output: movie_mux.mkv cu SRT bake-in soft

  C) Asamblare din raw streams HEVC + EAC3:
       1. Pune video.hevc + audio.eac3 in InputVideos
       2. Mux: video=video.hevc, audio=audio.eac3, target=mkv
       3. Output: video_mux.mkv (ffmpeg face wrap automat)


  ─── 10.18. Mux: limitari cunoscute ───

    - Toate streams trebuie sa fie in InputVideos. Daca vrei sa
      reusezi output-uri demux, mutati-le manual din OutputVideos
      → InputVideos. Decizie design: previne confuzie intre
      surse si artefacte.
    - Manual selection only — nu exista auto-grouping by basename
      (movie_v0_*.mkv + movie_a0_*.mka). Foloseste numele
      complete cum apar in lista.
    - VobSub pair (.idx + .sub) doar prin .idx in lista; daca
      lipseste .sub langa .idx, ffmpeg va esua la mux.
    - Attachments doar pe MKV. Pe mp4/mov/webm vor fi ignorate
      cu warning, mux continua fara ele.
    - Chapters XML pe mp4/mov: ffmpeg face conversie automata, dar
      formatul nativ MP4/MOV nu suporta toate feature-urile Matroska
      (nested editions, language tag pe ChapterDisplay).

  ─── 11.1. Transform RPU profile ───

  Cazuri tipice:
    - Ai DV Profile 5 si vrei sa-l converti la 8.1 cu HDR10 base.
    - Ai DV 8.1 si vrei o conversie fidela care pastreaza maparea de
      tonalitate (luma/chroma mapping).
    - Ai HEVC DV 8.1 si vrei AV1 DV Profile 10 echivalent.
    - Ai DV Profile 7 (dublu-strat, de pe disc UHD) si vrei 8.1 universal (v76).

  Modes oferite (dovi_tool 2.x; -m este flag global inainte de subcomanda):
    1) Force 8.1 (removes mapping, + HDR10 base)    [-m 2]
    2) DV 5 → 8.1                                   [-m 3]
    3) 8.1 pastrand maparea luma/chroma             [-m 5]
    4) Pentru AV1: profile 10 (sven-pke fork)       [-m 2 + tool av1]

  Nota: conversia 5 / 8.x se face prin "editor" de RPU (mod global), nu prin
  subcomanda "convert" (care in 2.x opereaza pe fisiere HEVC, nu pe RPU).

  Profile 7 → 8.1 (v76, dual-layer aware): cand sursa e DV Profile 7
  (dublu-strat, tipic de pe disc UHD), optiunea apare automat in Transform RPU.
  Profile 7 nu e citit de multe televizoare / playere; 8.1 e compatibil
  universal. Conversia pastreaza imaginea HDR10 de baza + metadata Dolby Vision
  (renunta la al doilea strat, de enhancement). Garda de siguranta: pe sursele
  rare unde al doilea strat aduce informatie reala de luminozitate (FEL complex),
  eliminarea lui poate afecta tonemapping-ul → suita avertizeaza si cere
  confirmare inainte sa continue (ocolire automata: DV_P7_FORCE=1; pe restul —
  lossless — conversia se aplica direct). Cand sursa P7 e in container MKV e
  nevoie de mkvextract (vine cu acelasi installer MKVToolNix ca mkvmerge).
  Profile 7 = doar HEVC (AV1 DV e mereu single-layer Profile 10).

  v91: conversia P7→8.1 e validata acum cap-coada pe mostre FEL reale (atat
  ramura FEL_SAFE cat si FEL_COMPLEX a clasificatorului de enhancement layer),
  inclusiv encode-preserve pe sursa P7. In plus, cand pastrezi un P7 prin COPY
  (stream-copy, Remux, Trim & Concat), suita afiseaza o nota informativa:
  copy-ul pastreaza straturile 1:1, dar Profile 7 nu e decodat de
  televizoare / playere hardware direct din fisiere (doar playere PC:
  mpv/madVR) → pentru compatibilitate universala foloseste Transform RPU
  (P7→8.1). Nota nu blocheaza nimic, doar te indruma.

  AV1 Dolby Vision (v56 — reparat): injectarea stratului DV in AV1 omitea un
  octet de aliniere obligatoriu, iar decodorul (dav1d) ignora apoi DV-ul (se
  pierdea la redare/re-mux). Acum un modul intern re-adauga octetul imediat
  dupa injectare, chirurgical (HDR10+ din hibrizi NU este atins), deci DV
  supravietuieste corect. Necesita Python 3; daca lipseste, fluxul verifica
  si avertizeaza onest (in loc de "complet" fals). HEVC nu a fost afectat.

  Pipeline (3 pasi):
    1) Extract RPU sursa (codec-aware: HEVC → dovi_tool, AV1 → av1dovi_tool)
    2) Convert RPU
    3) Re-build video — extract video raw, inject RPU convertit, re-mux
       cu audio/sub/track-uri originale

  100% lossless pe video — modifici DOAR metadata Dolby Vision.


  ─── 11.2. Inspect metadata (read-only) ───

  Dump rapid pentru diagnoza:
    - ffprobe summary (codec, dimensiuni, color_transfer/primaries)
    - DV RPU summary (info -s): numar cadre, profil, versiune DM, numar
      scene, mastering display, niveluri luminozitate L1/L5/L6 — sumar
      agregat pe tot RPU-ul, nu pe un singur cadru
    - DV RPU export complet la JSON (OutputVideos/<nume>_rpu.json) pentru

    - HDR10+ verificare autoritara ("--verify"): PREZENTA / ABSENTA (v56),

  ─── 11.3. HDR10+ → DV hybrid (v45, no re-encode) ───

  Sintetizeaza un strat DV din metadata HDR10+ existenta si il
  injecteaza in bitstream FARA re-encode.

  Pipeline:
    1) Extract HDR10+ JSON (codec-aware tool)
    2) Generate DV RPU din scene descriptors HDR10+ (nivelul L6 — mastering
       display + MaxCLL/MaxFALL — preluat din metadata HDR10 reala a sursei
       cand exista; altfel BT.2020 1000 niti)
    3) Extract raw video (HEVC annex-B / AV1 IVF)
    4) Inject DV RPU
    5) Re-mux cu audio/sub/track-uri originale

  Rezultat:
    HEVC HDR10+ → HEVC hybrid (DV 8.1 + HDR10 + HDR10+)
    AV1  HDR10+ → AV1 hybrid (DV P10 + HDR10 + HDR10+)

  100% lossless pe video. Util pentru playere care prefera DV ca prim
  level cand sursa are doar HDR10+.

  AV1 Dolby Vision (v56 — reparat): vezi nota de la 11.1 — DV-ul pe AV1 este
  acum pastrat corect (reparatie automata a metadatei dupa injectare). In
  hibrid, DV + HDR10 + HDR10+ supravietuiesc toate trei. HEVC nu a fost afectat.


  ─── 11.4. Remove DV → HDR10 curat (v56) ───

  Scoate stratul Dolby Vision (enhancement layer + RPU) dintr-un fisier,
  pastrand intacte HDR10 static si — daca exista — HDR10+ dinamic.
  Util cand vrei un fisier HDR10 simplu, fara semnalizare DV (unele
  TV-uri / playere prefera HDR10 curat).

  Pipeline (3 pasi, fara re-encode):
    1) Extract raw video (HEVC annex-B / AV1 IVF)
    2) Remove DV (dovi_tool remove / av1dovi_tool remove)
    3) Re-mux cu audio/sub/track-uri originale; pe MP4/MOV se aplica tag
       video curat (hvc1 / av01) ca fluxul sa nu mai fie raportat ca DV

  HEVC + AV1. Output: OutputVideos/<nume>_nodv.<ext>


  ─── 11.5. Remove HDR10+ metadata (v56) ───

  Scoate metadata dinamica HDR10+ (SEI la HEVC / OBU_METADATA la AV1),
  pastrand HDR10 static si — daca exista — stratul DV.

  Pipeline (3 pasi, fara re-encode):
    1) Extract raw video
    2) Remove HDR10+ (hdr10plus_tool remove / av1hdr10plus_tool remove)
    3) Re-mux cu audio/sub/track-uri originale

  HEVC + AV1. Output: OutputVideos/<nume>_nohdr10plus.<ext>


  ─── 11.6. Plot DV metadata → PNG (v56) ───

  Genereaza un grafic PNG al metadata Dolby Vision din RPU:
    1) L1 — luminozitate dinamica (implicit)
    2) L2 — trims
    3) L8 — trims (necesita RPU CM v4.0)

  Diagnostic vizual al masterului DV de-a lungul clipului. Graficul este
  generat nativ de unealta (dovi_tool plot / av1dovi_tool plot), fara

  Output: OutputVideos/<nume>_dvplot_<tip>.png

  nu functionau (formatul ASS nu accepta suprascrierea marimii din exterior).

  ffmpeg -vf "ass='<path>'" — render libass nativ cu tot styling-ul ASS
  (positioning, fonts, karaoke effects). Optional text shaping (vezi 13.5).

  ─── 13.4. Flow Image subs (Bluray PGS / DVD VobSub) ───

  Zero deps Python — ffmpeg suficient. ffprobe folosit pentru scan
  embedded tracks (skip silent daca lipseste).

  Scan unificat per video:
    - Extern PGS:    <name>.sup langa video sau in OutputVideos
    - Extern VobSub: <name>.idx + <name>.sub (pereche) langa video sau
                     in OutputVideos
    - Embedded:      ffprobe enumerate streams subtitle din container,
                     detecteaza codec hdmv_pgs_subtitle (PGS) sau
                     dvd_subtitle (VobSub); per track entry separat
                     cu lang tag in label

  Per video pot fi multiple entries (ex: video.mkv cu 2 track-uri PGS
  + extern .sup = 3 entries, fiecare pickable independent).

  v91: fluxul PGS a fost validat cap-coada pe o mostra reala (subtitrare
  forced dintr-un Blu-ray) — overlay-ul arde corect subtitrarea bitmap in
  pixeli, iar analiza media / Demux / Remux o recunosc si o pastreaza
  (Remux: PGS ramane pe MKV, se dropeaza onest pe MP4/MOV unde bitmap-ul nu
  intra). Subtitrarile "3D" de pe un Blu-ray 3D sunt tot PGS, in structura
  BD — odata extrase (fisier .m2ts / .sup) merg pe aceeasi cale.

  Encoder dialog (3 + Anulare):
    1) libx265 CRF 23 medium [implicit]
    2) libx264 CRF 20 medium
    3) libsvtav1 CRF 30 preset 6
    4) Anulare

  ffmpeg filter dispatcher pe kind:
    - ext_pgs / ext_vob:
        -i video -i aux -filter_complex "[0:v][1:s]overlay[v]"
    - emb_pgs / emb_vob:
        -i video -filter_complex "[0:v][0:s:N]overlay[v]"
        unde N = subtitle-relative stream index (s:0, s:1, etc.)

  Bitmap subs = pre-rendered → fara optiuni de styling (font/size).
  Track selection only (lang tag afisat in label cand exista).

  Note:
    - .idx + .sub trebuie sa fie pereche (ambele non-empty) pentru a fi
      detectate. ffmpeg incarca .sub automat cand primeste .idx.
    - Embedded MKV/MP4 multi-lang: fiecare track PGS/VobSub apare ca
      entry separat. Pentru SRT-uri embedded text (codec subrip/ass)
      foloseste extragere externa intai (mkvextract), apoi SRT/ASS flow.
    - Output naming: <name>_subs.<ext> (acelasi ca SRT/ASS — toate
      sunt subtitle burn-in).

  ─── 13.5. Text shaping (SRT + ASS, v82) ───

  Pentru scripturi complexe — araba, ebraica, limbi indice — unde forma
  literelor depinde de context sau textul curge dreapta→stanga, ffmpeg
  (libass cu HarfBuzz) poate aseza corect glifele. Prompt la fluxurile
  SRT si ASS, 3 variante:
    1) auto [implicit]  — comportamentul de pana acum (fara override)
    2) simple           — shaping de baza
    3) complex          — shaping complet HarfBuzz (RTL, ligaturi)

  Se adauga ca optiune de filtru: subtitles=...:shaping=<val> (SRT) sau
  ass=...:shaping=<val> (ASS). Promptul apare DOAR daca ffmpeg-ul tau
  suporta optiunea (gate pe "ffmpeg -h filter=subtitles"); altfel e sarit
  tacut. Pe "auto" nu se schimba nimic fata de versiunile anterioare.

  ─── 13.6. Preview mode (opt-in pe toate 4 flow-uri) ───

  Dupa encoder dialog, fiecare flow ofera o previzualizare:
    - HUD: meniu cu 3 variante — 0) niciuna (render complet) /
      1) still layout (o singura imagine, rapid; v81) / 2) clip 5s.
    - SRT/ASS/Image: prompt y/N pentru clipul de 5s (ca pana acum).

  (1) Still layout (HUD, v81) — verificare INSTANT a aspectului:
    - Se randeaza UN singur cadru HUD la mijlocul clipului si se
      compune peste cadrul video extras din acelasi moment →
      <name>_preview.png, deschis automat. Fara encodare video →
      rezultat imediat.
    - Optional, o grila de pozitionare (linii la 25/50/75% + px +
      colturile tl/tr/bl/br) ajuta la reglarea POS_* din preset.
    - Pe surse HDR in mod "preserve" imaginea de preview e adaptata
      automat pentru ecran normal (tonemap Hable, v82) ca sa nu iasa
      stinsa — un PNG nu poate purta HDR. Se schimba DOAR poza; output-ul
      real pastreaza HDR intact. Cu BURNIN_STILL_NO_TONEMAP=1 obtii poza
      bruta, netratata.

  (2) Clip 5s (toate flow-urile) — cand activ:
    - Output naming distinct: <name>_preview.<ext> (vs _hud / _subs)
    - HUD: render PNG seq doar pentru fereastra preview (5s la mid),
      cu --offset shiftat la t_start astfel ca frame 1 sa reprezinte
      CSV-ul la momentul preview. ffmpeg -ss t_start -t 5 pe video +
      PNG seq scurta, aliniate la t=0 in output.
    - SRT/ASS/Image: ffmpeg -ss t_start -copyts -t 5 -i video [...].
      Flag-ul -copyts pastreaza PTS-urile originale pt ca subtitle
      filters (subtitles=, ass=, overlay pe stream sub) sa aleaga
      corect subtitle-ul de la momentul preview.

  Caz limita: video < 5s → fereastra = (0, min(5, durata)).

  Utilitate: economiseste ore cand stilul/track-ul/sync offset-ul e
  gresit. User verifica preview-ul de 30-60 sec, apoi re-ruleaza
  flow-ul fara preview pentru full encode.

  Mode batch: daca user selecteaza ALL + preview, fiecare fisier
  primeste propriul <name>_preview.<ext> de 5s.

  BURNIN_STILL_NO_TONEMAP=1 → cadru brut si in designer.

  Note:
    - Elementele de colt (timestamp/viteza/ALT/HDG/TEMP) sunt inactive
      cat timp data-strip e pornit (sunt deja in strip) — pagina le
      arata estompate, cu explicatie.
    - Fara GPS in telemetrie → harta nu se poate desena (pagina te
      anunta onest).
    - Port implicit: efemer (liber automat); optional --port N la

  ─── 14.1. Windows PS1 — NVENC / QSV / AMF (v35) ───

  Meniu encoder optiunea 6 in av_encode.ps1.
  Detectie dubla: ffmpeg binary + GPU fizic (WMI Win32_VideoController).
  Filtreaza adaptoare virtuale (RDP, VMware, VirtualBox, Hyper-V, Citrix,
  DisplayLink, Parsec).

  Encodere disponibile:
    NVIDIA NVENC: hevc_nvenc / h264_nvenc / av1_nvenc
    Intel QSV:    hevc_qsv   / h264_qsv   / av1_qsv
    AMD AMF:      hevc_amf   / h264_amf   / av1_amf

  Rate control: QP (Quality Parameter), NU CRF. Recomandat 18-28.
  Preset: NVENC p1-p7 / QSV veryfast-veryslow / AMF speed-balanced-quality.
  10-bit automat (p010le) pe NVENC/QSV si AV1 AMF daca sursa e 10-bit.

  AV1 HW — cerinte generatie:
    NVIDIA: RTX 40+ (Ada) sau mai nou (RTX 50, L4, L40)
    Intel:  Arc A/B, Core Ultra (Meteor/Arrow/Lunar Lake)
    AMD:    RDNA3+ (RX 7000/8000/9000, W7000, iGPU 740M..890M)

  v77 — probe functional: pe langa potrivirea dupa numele placii, suita
  verifica acum capabilitatea REALA printr-un micro-encode AV1 la pornire
  (testsrc -> encoder HW -> null). Daca numele placii nu e recunoscut de
  liste dar encoderul chiar merge, AV1 HW e activat automat; daca e listat
  dar pica la rulare, cade curat pe software. Ruleaza DOAR cand numele nu e
  recunoscut (cost zero pe placile stiute) si nu poate da fals-pozitiv (un
  encoder incapabil pica clar). v75 il avea doar pe Intel (Linux); v77 il
  extinde la NVENC / AMF / VideoToolbox + calea Windows (toate vendorii).

  Banner GPU la startul fluxului encode cu lista HW per-codec.
  Optiuni indisponibile listate gri cu motiv: "necesita RTX 40+ (Ada)",
  "necesita RDNA3+", "GPU absent".

  Fallback automat la SW echivalent cand GPU nu suporta:
    hevc_* → libx265 / h264_* → libx264 / av1_* → libsvtav1

  Profile field HW_FORCE=1: bypass detection (util pt GPU-uri noi
  ne-detectate de regex-ul intern).


  ─── 14.2. MediaCodec (Termux/Android, v38/v39) ───

  Meniu HW in launcher post-encoder selection (SW vs MediaCodec).
  Detectie: Termux + getprop + binary check.

  Per-codec mapping:
    x265 → hevc_mediacodec   (8-bit + 10-bit pe SoC verificat)
    x264 → h264_mediacodec   (8-bit only, SDR only)
    av1  → av1_mediacodec    (rar, doar SoC AV1-capable)

  SoC WHITELIST (HEVC 10-bit HW encode, marcat [verificat] in meniu):
    Snapdragon 8xx (8 Gen 1+)
    Exynos 2100+ (recunoscut si dupa codename s5e9...)
    Tensor G2+
    Dimensity 9000+
  AV1 HW ENCODE nu se mai revendica pe niciun SoC (v75) — vezi nota de mai jos.

  Detectia citeste ro.soc.manufacturer / ro.soc.model + ro.hardware.
  Nota (v75, validat pe hardware real): producatorul Qualcomm e raportat
  pe device-urile recente ca "QTI" (nu "Qualcomm") — recunoscut acum,
  altfel flagship-ul Snapdragon (ex. S24 Ultra / 8 Gen 3) cadea pe
  [suport necunoscut]. Samsung raporteaza in ro.soc.model NUMELE DE COD
  al cipului (ex. A54 = s5e8835; Exynos 2100 = s5e9840, 2200 = s5e9925,
  2400 = s5e9945), nu numele comercial "exynos2100" — flagship-urile
  Exynos sunt recunoscute acum si dupa codename.

  SoC necunoscut: marcat [suport necunoscut], prompt confirmare la
  alegere (default NU). Bypass: HW_FORCE=1.

  IMPORTANT: prezenta unui encoder MediaCodec in lista ffmpeg NU
  garanteaza suport hardware. Pe un SoC fara unitate dedicata, MediaCodec
  cade transparent pe encoder software; spre deosebire de QSV, care esueaza
  direct pe hardware lipsa. Eticheta [verificat] reflecta suportul HARDWARE
  cunoscut al cipului, nu simpla prezenta a encoderului.

  AV1 HW ENCODE pe mobil (v75): cvasi-inexistent. Decode-ul e raspandit
  (8 Gen 2+, Dimensity 9000+, Exynos 2200+, Tensor G3+), dar encode-ul
  aproape nicaieri — infirmat empiric pe Snapdragon 8 Gen 3 (S24 Ultra:
  doar c2.qti.av1.DECODER in /vendor; av1_mediacodec = c2.android.av1.encoder
  software libaom, 1.68x la 1080p vs h264 HW 4.81x) si Exynos 1380 (A54).
  De aceea suita nu mai ghiceste AV1 HW din modelul SoC, ci il detecteaza
  DIRECT din lista de codecuri a telefonului (un encoder AV1 hardware, non-
  software, in /vendor/etc/media_codecs). Cand alegi av1_mediacodec, daca
  cipul n-are encoder AV1 HW, fluxul cade automat pe libsvtav1 (encoderul SW
  al suitei — calitate mai buna + control total decat libaom-prin-MediaCodec).
  Forward-compat: daca un telefon viitor expune un encoder AV1 hardware, suita
  il foloseste de la sine, fara update. Override manual: HW_FORCE=1.

  PIERDERI REALE (universale MediaCodec, nu chip-specific):
    HDR10+ dynamic metadata (per-frame) — imposibil via API public Android
    Dolby Vision native preservation    — necesita licenta Dolby (libdovi privat)

  TOT RESTUL FUNCTIONEAZA:
    HDR10 static (cu signaling repair via hevc_metadata bsf post-encode)
    HEVC 10-bit main10 (semnalizare + container 10-bit)
    AV1 SDR (doar pe SoC cu AV1 encode HW REAL — rar; altfel fallback libsvtav1)
    HLG nativ (v39 — signaling in transfer chars, fara SEI repair)

  PRECIZIE 10-BIT la intrare (v75): encoderele MediaCodec din ffmpeg
  accepta DOAR intrare 8-bit (mediacodec / yuv420p / nv12) — orice sursa
  10-bit e convertita automat la 8-bit inainte de encoder (verificat pe
  Snapdragon 8 Gen 3 si Exynos 1380). Output-ul HDR10 / HLG e marcat si
  ambalat ca 10-bit (signaling corect, recunoscut de TV), dar precizia
  reala e 8-bit → posibil banding pe HDR real. Hardware-ul chiar ARE bloc
  encode HDR (ex. nod c2.qti.hevc.encoder.hdr pe Snapdragon), insa ffmpeg
  nu-l poate hrani pe calea cu filtre. Pentru HDR fara banding: software.
  Forward-compat: suita verifica automat formatele de intrare ale encoderului
  — daca o versiune viitoare de ffmpeg adauga intrare 10-bit, MediaCodec o va
  folosi de la sine, fara modificari.

  Dialog HDR MediaCodec (DV / HDR10+ / HLG / HDR10):
    1) SW libx265 — pastrare completa (recomandat default)
    2) SW libx265 — strip enhancement (DV→HDR10 BL, HDR10+→HDR10 static)
    3) MediaCodec — HDR10 / HLG nativ + signaling repair
    4) MediaCodec — SDR tonemap 8-bit (proxy rapid)
    5) Skip

  x264 special: h264_mediacodec NU suporta HDR → auto-tonemap.
  AV1: whitelist-ul nu mai revendica AV1 HW encode (v75) → cand cipul n-are
  unitate AV1 encode (cazul uzual pe mobil), fluxul cade automat pe libsvtav1.

  Profile bypass MEDIACODEC_HDR_POLICY:
    sw_full | sw_degraded | hw_repair | hw_hlg (v39) | hw_sdr | skip

  ─── 14.5.1. HW DV preserve (v46) ───

  Toate 6 HW backends (NVENC/QSV/VAAPI/VT/AMF/MediaCodec) suporta acum DV
  preserve cand target codec este HEVC sau AV1. Pipeline-ul:

    1. extract_dv_rpu(sursa) — codec-aware (dovi_tool HEVC, av1dovi_tool AV1)
    2. HW encode produce HDR10 base layer (10-bit p010le)
    3. (MediaCodec only) repair_hdr10_signaling — SEI mastering_display + max_cll
    4. inject_dv_rpu(output, RPU) — post-encode handler in run_encode_loop

  Gate (HEVC sau AV1 target + tool DV pt sursa + tool DV pt target):
  cand gate=0 dialogul afiseaza meniu redus fara opt hw_preserve (renumerotat
  dinamic ca sa nu skip numere). Fallback automat la hw_hdr10 cand policy=
  hw_preserve dar tool indisponibil.

  Acopera 12 combinatii: 6 backends × {HEVC target, AV1 target}.


  ─── 14.5.2. HW HDR10+ preserve via inject (v76) ───

  Orice encoder hardware dropeaza metadata dinamica HDR10+ (ramane doar HDR10
  static — luminozitate fixa pe tot filmul). v76 o restaureaza prin acelasi
  pattern ca DV preserve:

    1. extract HDR10+ JSON din sursa (codec-aware: hdr10plus_tool HEVC,
       av1hdr10plus_tool AV1)
    2. HW encode produce baza HDR10 (PQ 10-bit)
    3. post-encode: re-inject HDR10+ peste bitstream-ul encodat hardware
       (pe AV1 se re-adauga si octetul de aliniere T.35, exact ca la DV)

  Gate: target HEVC/AV1 + hdr10plus_tool pt sursa SI target. Cand unealta e
  prezenta, pe o sursa HDR10+ + HW pastrarea via inject e optiunea IMPLICITA
  (ai ales deja HW; metadata re-injectata e identica cu sursa) — sw_full
  coboara pe pozitia 2.

  Hibrid DV + HDR10+ pe HW: sursa hibrida intra pe hw_preserve (DV are
  prioritate) si lantul re-injecteaza ambele straturi peste baza HW — intai
  HDR10+, apoi DV RPU — cu semnalizare de container (dvcC) la final pe MKV/MP4.

  Validat empiric pe QSV HEVC (boxa Intel). NVENC / AMF / VAAPI / VideoToolbox
  + AV1 HW = la nivel de specificatie (acelasi pattern). Bypass:
  HW_HDR_POLICY=hw_preserve (pe sursa HDR10+ se ruteaza automat la HDR10+
  preserve; pe DV → DV preserve).


  ─── 14.5.3. Avertisment frame-rate variabil (VFR) (v77) ───

  La pastrarea metadatei dinamice prin extract→inject (HW HDR10+, DV preserve
  si hibrid), metadata se extrage din cadrele CODATE ale sursei si se aplica
  pe POZITIE peste baza re-encodata. Pe o sursa VFR (r_frame_rate diferit de
  avg_frame_rate) numarul de cadre poate diferi cu cateva la coada → uneltele
  (hdr10plus_tool / dovi_tool) aliniaza automat (dup/skip la coada) → output
  valid, fara impact vizibil. Suita avertizeaza acum cand sursa e VFR, ca sa
  stii la ce sa te astepti — NU normalizeaza la CFR (ar schimba output-ul pe o
  cale de pastrare). Pe APV diferentele mici de cadre se aliniaza la fel
  (metadata dinamica e pastrata, bounded-graceful ca DV/HW); doar pe o
  nepotrivire mare — semn ca metadata nu provine din acelasi fisier — APV
  cade pe HDR10 static (praguri APV_ALIGN_MIN_FRAMES=8 / APV_ALIGN_MAX_RATIO=
  0.02 in engine). Caile encode-time (x265 dhdr10-info / svtav1 hdr10plus-json)
  nu sunt afectate.

  ─── 15.1.1. AV_PROFILE env var (v52) — non-interactive auto-load ───

  Pentru CI/cron/batch overnight: lanseaza launcher-ul cu profil
  pre-selectat fara prompt-uri interactive.

    Bash:
      AV_PROFILE=drone_4k bash av_launcher.sh
      AV_PROFILE=/path/abs.conf bash av_launcher.sh < /dev/null

    PowerShell:
      $env:AV_PROFILE = "drone_4k"; .\av_encode.ps1

  Acceptat formate:
    - Path absolut .conf: AV_PROFILE=/home/user/myprofile.conf
    - Nume fara .conf:    AV_PROFILE=drone_4k
    - Nume cu .conf:      AV_PROFILE=drone_4k.conf

  Resolve order:
    1. Path direct (Test-Path / [ -f ])
    2. UserProfiles/<name>.conf (user overrides built-ins)
    3. src/profiles/*/<name>.conf (built-in DJI Action 6, etc.)

  Comportament:
    - EXTENDS chain rezolvat (root→leaf, leaf overrides parent)
    - Schema validation pe fiecare link in chain
    - Auto-confirm — bypass user prompt "Lanseaza cu aceste setari?"
    - Direct la encode, fara meniuri intermediare
    - LUT fail-fast: daca profilul cere LUT si lipseste din Luts/,
      exit 1 cu mesaj (non-interactive context)

  Pentru tweak partial fara override profil:
    Foloseste profilul ca template + edit .conf inainte de rulare.
    NU exista override per-field env var (decizie design: profilurile
    sunt unitati atomice).

  Diferenta vs profile load interactive (din meniu):
    - Profile load interactive: prompt selectie + confirm la launch
    - AV_PROFILE auto-load: zero prompt-uri, direct la encode


  ─── 15.2. Schema validation ───

  Schema declarativa per camp (enum / regex / int / intrange / string /
  path). Validare per linie inainte de load.

  Cheile necunoscute = WARNING (forward-compat, nu eroare).
  Valori invalide = EROARE → user primeste prompt daca continua sau anuleaza.

  Non-interactive guard: detecteaza stdin redirectat sau AV_NONINTERACTIVE=1
  si face fail-fast in loc sa blocheze pe prompt — sigur pentru CI/scripting.


  ─── 15.3. EXTENDS — Profile inheritance ───

  EXTENDS=parent_name in profil child. Profilul child mosteneste TOATE
  campurile parintelui; cele suprascrise local au prioritate.

  Rezolutie parinte: sibling dir → UserProfiles/ → src/profiles/*/.
  Override semantics: root → leaf (leaf wins).
  Cycle detection cu path canonicalization (corect pe Windows/macOS
  case-insensitive — recunoaste "./dir/x.conf" si "DIR/x.conf" ca acelasi).
  Depth limit: 5.

  Lant >1 link → afiseaza secventa "root → leaf" inainte de source.


  ─── 15.4. Bypass fields pentru batch / CI ───

  HW_HDR_POLICY             — bypass dialog HDR pe backend-uri HW v42
  MEDIACODEC_HDR_POLICY     — bypass dialog HDR pe MediaCodec (v38/v39)
  DOVI_PRESERVE_POLICY (v45) — bypass dialog DV (auto/preserve/convert/copy/skip)
  HW_FORCE                  — bypass detection GPU/SoC

  Toate sunt opt-in. Default = dialog interactiv per fisier.


  ─── 15.5. profile_diff CLI ───

  Utilitar in src/tools/profile_diff.{sh,ps1} pentru comparat doua
  profile .conf:

    ./tools/profile_diff.sh A.conf B.conf
    .\tools\profile_diff.ps1 A.conf B.conf

  Raport cu sectiuni:
    "Doar in A" — chei prezente doar in A
    "Doar in B" — chei prezente doar in B
    "Valori diferite" — chei comune cu valori diferite

  Exit codes: 0=identice / 1=diferente / 2=invalid args.


  ─── 15.6. Tests (v43) ───

  Framework bash + PS1 mirror in tests/.

  Rulare:
    bash tests/fixtures/generate_samples.sh && bash tests/run_tests.sh
    .\tests\fixtures\generate_samples.ps1; .\tests\run_tests.ps1

  Discover automat in unit/, integration/, hw/. Per-test log + summary.
  Test-urile dependente de ffmpeg/ffprobe/exiftool auto-skip cand binarul
  lipseste — runner raporteaza ca "~ skip: <reason>".

19. TROUBLESHOOTING
═══════════════════════════════════════════════════════════════

  PROBLEMA: "Permission denied" la rulare script
  SOLUTIE:  chmod +x src/*.sh src/tools/*.sh

  PROBLEMA: "command not found: ffmpeg"
  SOLUTIE:  Termux:        pkg install ffmpeg -y
            Linux:         apt/dnf/pacman install ffmpeg
            macOS:         brew install ffmpeg
            Windows:       adauga in PATH

  PROBLEMA: PS1 nu se ruleaza ("execution of scripts is disabled")
  SOLUTIE:  Set-ExecutionPolicy -Scope CurrentUser -ExecutionPolicy RemoteSigned
            (ruleaza o singura data in PowerShell ca Administrator)

  PROBLEMA: termux-wake-lock nu functioneaza
  SOLUTIE:  pkg install termux-api + instaleaza aplicatia Termux:API din F-Droid
            (versiunea Play Store nu functioneaza)

  PROBLEMA: macOS bash fails at startup ("Refuza bash 3.x")
  SOLUTIE:  brew install bash (default macOS este 3.2, nesuportat)

  PROBLEMA: "Nu am gasit fisiere video"
  SOLUTIE:  Termux:       pune fisierele in /storage/emulated/0/Media/InputVideos/
            Linux/macOS:  pune fisierele in $SCRIPT_DIR/InputVideos/
            Windows:      pune fisierele in folderul cu scriptul

  PROBLEMA: Fisierele DJI pierd metadata GPS/telemetrie
  SOLUTIE:  Track-urile DJI (djmd/dbgi/tmcd) au codec "none" — incompatibile
            cu mp4/mov. Alege mkv sau accepta "Schimba la MKV" din dialog.
            Metadatele raman in fisierul original.

  PROBLEMA: Subtitrari PGS/DVDSUB pierdute la mp4/mov
  SOLUTIE:  Normal — PGS/DVDSUB sunt incompatibile cu mp4/mov.
            Scripturile le omit automat (-sn). Foloseste mkv pentru a pastra.

  PROBLEMA: Cum pastrez Dolby Vision complet?
  SOLUTIE:  Alege "Stream copy video" in dialogul DV — video-ul nu se
            re-encodeaza, doar audio-ul.
            Pentru re-encode cu DV preserve (v45): opt 3 "DV preserve (HEVC 8.1)"
            sau pentru AV1: opt 3 "DV Profile 10 (AV1)" (necesita dovi_tool /
            av1dovi_tool pentru sursa).

  PROBLEMA: Export GPS genereaza fisiere goale
  SOLUTIE:  Fisierul video nu contine date GPS. Pe DJI Action 6 (fara
            senzor GPS intern), datele se salveaza DOAR daca ai filmat
            cu telecomanda DJI Bluetooth conectata sau cu aplicatia DJI
            Mimo pornita pe telefon. Cand exista GPS, se exporta traseul
            complet (GPX/SRT/CSV basic + normalizat cu viteza/directie/
            G-force), nu doar un singur punct.

  PROBLEMA: AV1 HDR10+ inline missing
  SOLUTIE:  Requires SVT-AV1 v1.5+. libaom-av1 falls back to HDR10 static
            automatically. Update ffmpeg pentru SVT-AV1 v1.5+.

  PROBLEMA: "av1dovi_tool not found" sau "av1hdr10plus_tool not found"
  SOLUTIE:  Installer cu cargo: ./tools/av1dovi_parser.sh sau .ps1.
            Necesita Rust toolchain (rustup) si git.

  PROBLEMA: profile load esueaza pe Windows / macOS (cycle false-positive)
  SOLUTIE:  Path canonicalization fixat in v43 — pe Windows si macOS
            case-insensitive, "./dir/x.conf" si "DIR/x.conf" recunoscute
            ca acelasi fisier. Verifica daca ai v43+ in cod.

  PROBLEMA: Test runner blocheaza pe prompt-uri param-mandatory
  SOLUTIE:  Runner PS1 foloseste -NonInteractive automat.
            Pentru bash CI: export AV_NONINTERACTIVE=1 inainte de tests/run_tests.sh.

  PROBLEMA: Uneltele externe sunt instalate sub alt nume / alta cale
            (ex. distro-ul livreaza "dovi-tool" in loc de "dovi_tool")
  SOLUTIE:  v69 — numele tuturor uneltelor externe sunt configurabile prin
            variabile de mediu (accepta nume simplu sau cale completa):
              AV_TOOL_DOVI          (default: dovi_tool)
              AV_TOOL_HDR10PLUS     (default: hdr10plus_tool)
              AV_TOOL_AV1DOVI       (default: av1dovi_tool)
              AV_TOOL_AV1HDR10PLUS  (default: av1hdr10plus_tool)
              AV_TOOL_EXIFTOOL      (default: exiftool)
              AV_TOOL_OAPV_DEC      (default: oapv_app_dec — optional)
              AV_TOOL_SVTAV1ENCAPP  (default: SvtAv1EncApp — doar caps-probe)
              AV_TOOL_MKVMERGE      (default: mkvmerge — optional, dvcC DV pe MKV)
              AV_TOOL_MKVEXTRACT    (default: mkvextract — optional, extract strat P7 BL+EL+RPU pt conversia 7→8.1, v76)
              AV_TOOL_MP4BOX        (default: mp4box — optional, dvcC DV pe MP4/MOV, v71)
              AV_ENGINE_APV_HDR10PLUS (default: src/apv_hdr10plus.py)
              AV_ENGINE_DV_P7       (default: src/dv_p7_analyze.py — clasificare strat P7 MEL/FEL, v76)
            Exemplu: AV_TOOL_DOVI=dovi-tool bash av_launcher.sh
            Windows: $env:AV_TOOL_DOVI = "C:\tools\dovi_tool.exe"

  PROBLEMA: La encodarea APV cu HDR10+ nu apare "decode-check referinta"
  SOLUTIE:  Pasul e OPTIONAL si tacut — apare doar daca decodorul de
            referinta OpenAPV (oapv_app_dec) e instalat. Ruleaza
            tools/openapv_validator.sh / .ps1. Verificarea principala
            (re-extragere + comparare metadata) ruleaza oricum.
